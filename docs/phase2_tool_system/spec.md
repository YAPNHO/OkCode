# OkCode 第二阶段：工具系统 Spec

## 背景

OkCode 已经完成第一阶段的终端多轮对话、统一 Provider 抽象、OpenAI/Anthropic 流式适配和进程内会话历史。当前模型只能生成文本，无法读取项目、修改文件、执行命令或搜索代码，因此还不是能够实际完成编程任务的 Agent。

本阶段将在现有对话能力之上加入最小可用的工具系统：模型可根据用户问题选择一个合适的工具，OkCode 执行该工具，将结构化执行结果回传给模型，并结束本次请求流程。这样既建立模型调用本地能力的完整链路，也刻意不提前引入下一章的自动 Agent Loop。

## 目标

- 为 OkCode 提供统一的工具描述、参数声明和执行能力，使工具能被集中注册、查询和暴露给模型服务。
- 提供六项本地开发核心能力：读取文件、写入文件、按唯一原文替换修改文件、执行命令、按模式查找文件、搜索代码内容。
- 支持 OpenAI 与 Anthropic 协议下的流式工具调用：正确处理流中分片到达的 JSON 参数，并将一次工具调用及其结果纳入当前对话历史。
- 工具成功、参数错误、超时、未知工具、文件操作失败、命令执行失败等情况，均以模型可理解的结构化结果返回，而不导致 OkCode 崩溃。
- 本章每次模型请求最多执行一次工具调用；工具结果回灌后不自动请求模型继续推理，后续的多步自动循环留给下一章。

## 功能需求

- **F1：统一工具能力描述**  
  系统中的每个工具都以统一形式提供：唯一名称、面向模型的用途说明、JSON 参数 Schema，以及接收参数并产生执行结果的能力。工具元信息可被转换为 OpenAI 和 Anthropic 各自认可的工具声明格式。

- **F2：核心工具集**  
  首版必须提供以下六个可由模型调用的核心工具：

  | 工具能力 | 行为 |
  |---|---|
  | 读文件 | 按路径读取文本文件内容，并返回内容或可诊断错误。 |
  | 写文件 | 按路径创建或完整写入文本文件；需要时自动创建缺失的父目录。 |
  | 改文件 | 在指定文件内按原文进行精确替换：仅当待替换原文恰好出现一次时才修改；出现零次或多次时不写入文件，并返回清楚的失败原因。 |
  | 执行命令 | 在工作区内执行模型给出的命令，采集标准输出、标准错误、退出状态和超时状态。 |
  | 找文件 | 根据模式在工作区内查找匹配的文件路径。 |
  | 搜代码 | 根据查询文本在工作区文件中搜索匹配内容，并返回命中的文件、行号和匹配行。 |

- **F3：注册与发现**  
  系统通过一个集中注册中心登记可用工具。调用方能够按名称查找工具、获得所有工具的模型声明，并拒绝重复名称或不存在的工具。

- **F4：工作区边界**  
  文件读取、写入、修改、查找和搜索均以 OkCode 启动时的当前工作区为边界；工具不得通过相对路径跳出该目录访问任意位置。执行命令默认也以工作区为当前目录运行。

- **F5：结构化执行结果**  
  无论工具成功还是失败，执行层都返回统一、可序列化的结果，至少包含成功状态、给模型阅读的结果内容，以及必要的错误类别。失败不是进程异常：例如参数不合法、文件不存在、路径越界、唯一替换不成立、命令非零退出、命令超时、找不到工具，都会变成可回灌给模型的工具结果，使模型能够在下一次请求中调整方案。

- **F6：工具执行的超时与异常隔离**  
  工具执行应有明确的超时限制；超时后返回结构化的超时结果。单个工具内部异常不得令 REPL、会话或 Provider 客户端崩溃。命令工具即使以非零状态退出，也应把已捕获的输出和退出状态返回给模型，而不是把它误判为 OkCode 自身故障。

- **F7：OpenAI 流式工具调用**  
  当 OpenAI 兼容服务在流中返回工具调用时，OkCode 必须按调用标识拼接名称和分片到达的 JSON 参数；仅在流结束并得到完整参数后解析、校验和执行。当前轮的助手工具调用消息，以及与其对应的工具执行结果，都必须以 OpenAI Chat Completions 认可的消息形式保存到会话历史。

- **F8：Anthropic 流式工具调用**  
  当 Anthropic Messages 流返回工具调用时，OkCode 必须识别工具使用块、累积其 JSON 输入分片，并在输入完整后执行。当前轮的助手工具使用块及对应的用户工具结果块必须保留为 Anthropic 所需的历史状态，保证下一次模型请求的上下文合法。

- **F9：单次调用与结果回灌**  
  本章每次用户提交问题后，模型最多可发起一次工具调用。OkCode 执行后，将“助手的工具调用”和“工具结果”一并提交到当前进程内会话历史；本次交互到此结束并恢复输入状态。若模型直接返回文本，则维持第一阶段的普通对话行为。模型拿到工具结果后自动再次调用模型、连续选取其他工具、直至产出最终自然语言回答，明确留给下一章。

- **F10：工具调用失败的历史一致性**  
  即使工具执行失败，只要模型已合法发起该调用，也要将该调用及其结构化失败结果成对写入会话历史。这样下一次请求中模型能知道失败事实，并能修正参数或改用其他方案；不得留下只有工具调用、没有对应结果的无效消息序列。

## 非功能需求

- **N1：参数校验与可诊断性**  
  工具参数在执行前必须按自身 Schema 校验。参数缺失、类型错误、JSON 无法解析或包含不允许字段时，应返回明确的结构化失败结果，说明工具名、错误类别和可修正的原因；不得把原始异常堆栈直接展示给模型或终端用户。

- **N2：执行稳定性**  
  文件工具、搜索工具、命令工具和 Provider 工具调用解析之间应相互隔离。任一工具失败、超时或产生非零命令退出状态后，OkCode 仍保持可继续输入和发起下一轮请求的状态。

- **N3：超时与输出边界**  
  可能阻塞的工具必须在有限时间内结束。命令超时后应终止被启动的命令并返回超时结果。工具返回给模型的内容应有大小上限；超出时保留可理解的截断提示，避免一次大文件、海量搜索结果或命令输出耗尽会话上下文。

- **N4：文件修改原子性**  
  “改文件”工具在确认原文唯一匹配之前不得写入文件；替换过程中出现异常时不得留下半写入或部分替换的文件内容。写文件和改文件成功结果应包含可验证的路径与修改摘要。

- **N5：工作区安全性**  
  所有文件相关工具必须验证最终解析后的路径仍在工作区内，不能被 `..`、绝对路径、符号链接或等价路径形式绕过。错误信息不应泄漏工作区外的文件内容。命令工具的执行目录固定为工作区，但本章不承诺实现操作系统级沙箱；因此它是受用户主动使用 OkCode 授权的本地开发能力，而非针对不可信提示的安全隔离方案。

- **N6：协议兼容与可扩展性**  
  具体工具无需了解 OpenAI 或 Anthropic 的消息结构；协议差异集中于 Provider 适配层。新增工具不应要求改动已有工具的实现；新增协议不应要求重写工具注册、执行或结构化结果机制。

- **N7：可测试性**  
  工具注册、参数校验、路径边界、唯一替换、超时与执行结果，以及两种协议的流式工具参数拼接和历史回灌，都应能在不访问真实模型服务、不执行危险真实命令的条件下自动测试。

## 不做的事

本阶段明确不包含：

- 自动 Agent Loop：不在工具结果回灌后再次请求模型，也不自动持续执行到得到最终自然语言回答。
- 同一轮执行多个工具调用、并行工具调用、工具之间的自动依赖编排。
- 用户确认式权限系统、命令白名单、Docker/虚拟机隔离、网络隔离或操作系统级沙箱。
- Git 专属工具、提交/回滚、补丁格式解析、目录删除、文件移动/重命名。
- 二进制文件编辑、图片/PDF/Office 文档解析、多模态工具输入。
- 超大仓库索引、语义检索、向量数据库、缓存式搜索结果或跨会话工具记忆。
- 多工作区切换、通过工具读取工作区外内容、工具权限持久化。
- 工具结果的自动摘要、上下文压缩或保存到磁盘。
- 对所有第三方 OpenAI/Anthropic 兼容服务的私有工具调用扩展逐一兼容；本章只支持两种官方协议对应的标准工具调用格式。

## 验收标准

- **AC1（F1、F3）**：登记工具后，可按名称取得工具，并可生成供 OpenAI、Anthropic 请求使用的工具声明；登记重名工具或查询不存在工具时，得到明确失败结果。
- **AC2（F2）**：六项核心工具可独立调用并产生预期结果：读取已有文本文件、写入新文件、唯一原文替换、在工作区执行命令、按模式发现文件、在文件内容中返回包含路径和行号的搜索命中。
- **AC3（F2、F5、N4）**：改文件时，原文恰好出现一次则完成替换；原文不存在或出现两次及以上时文件保持字节内容不变，结果明确说明“未匹配”或“匹配不唯一”。
- **AC4（F4、N5）**：对工作区外路径、包含路径回退的路径，以及最终解析后逃离工作区的符号链接路径进行读、写、改、找、搜时，工具均拒绝执行且不泄漏工作区外内容。
- **AC5（F5、F6、N1、N2）**：未知工具、非法参数、文件不存在、权限/IO 异常、命令非零退出、命令超时等情况，都返回包含 `success=false`、错误类别和可读原因的结构化结果；随后 OkCode 可继续接受下一条用户输入。
- **AC6（F6、N3）**：执行一个超过配置时限的测试命令后，命令被停止，结果标识为超时；执行输出超过上限的测试命令或搜索后，结果包含截断标记而不会无限增长。
- **AC7（F7）**：使用可控 OpenAI SSE 流，将同一工具调用的名称、调用标识和 JSON 参数拆分到多个增量中发送；OkCode 能正确拼接并仅在参数完整后执行一次相应工具。
- **AC8（F8）**：使用可控 Anthropic SSE 流，将工具输入拆分为多个 JSON 增量发送；OkCode 能还原完整输入、执行一次工具，并生成符合 Anthropic 后续请求要求的工具调用与工具结果历史。
- **AC9（F9）**：模型普通文本回复时，行为保持第一阶段一致，已完成的用户消息和文本回答正常进入历史；模型请求一次工具时，工具执行完成后 OkCode 回到输入状态，不自动向模型发送第二次请求。
- **AC10（F10）**：工具成功和工具失败两种情况下，下一轮模型请求的历史中都包含成对的“助手工具调用”与“对应工具结果”；不存在孤立的工具调用或孤立的工具结果。
- **AC11（N6、N7）**：在无真实网络条件下，自动化测试覆盖工具注册、六类工具、路径边界、唯一替换、超时、输出截断，以及 OpenAI/Anthropic 两套流式参数拼接和回灌历史。
- **AC12（端到端）**：用户在一个测试工作区提问“读取某文件并告诉我其内容”后，模型发起读文件调用；OkCode 显示工具执行状态、将读取结果写入本轮历史、恢复输入状态。随后可以通过检查下一次 Provider 请求验证该工具调用和结果已被正确回灌。
