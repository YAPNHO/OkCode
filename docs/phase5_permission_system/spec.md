# OkCode 第五阶段：五层权限系统 Spec

## 背景

OkCode 已具备工作区边界、文件读写、命令执行和多轮 Agent Loop。当前 `run_command` 会通过 Windows shell 执行模型给出的命令，文件工具虽已有基础工作区检查，但系统没有统一的权限决策层，无法表达用户对不同工具、命令模式和路径的信任范围，也无法在模型尝试危险操作时将决定权交回用户。

本阶段为 OkCode 增加一套五层防御的权限系统：不可配置放开的危险命令黑名单、路径沙箱、可配置规则、整体权限模式和人在回路确认。它必须适配 Windows：命令判断面向 Windows shell 文本，路径比较在解析符号链接后的规范化 Windows 路径上完成。权限拒绝是可供模型理解和纠正的工具结果，不应直接终止 Agent Loop。

## 目标

- 在所有本地工具实际执行前，按固定顺序作出允许、拒绝或请求用户确认的权限决定。
- 永久阻止已知高危命令和任何经符号链接解析后离开项目目录的文件访问。
- 支持按工具名与参数或路径模式定义 `allow`、`deny` 规则，并由用户级、项目级、本地级和会话级规则共同决定结果。
- 支持 `strict`、`default`、`allow` 三档整体权限模式，清晰控制未命中规则时的处理方式。
- 仅在没有明确规则结论时请求用户确认，并支持本次、本会话、永久三种放行范围。
- 保持现有 Agent Loop 的纠错能力：权限拒绝或用户拒绝要作为结构化工具失败回灌给模型，模型可以改用其他工具、参数或方案继续本轮任务。

## 功能需求

- **F1：统一权限决策入口**
  OkCode 必须在每个已注册本地工具的实际执行前完成权限检查。所有工具调用都要经过同一套决策流程，不能依赖模型提示词自行遵守，也不能只保护 `run_command`。允许的调用才可进入原有工具实现；拒绝的调用不得产生文件或命令副作用。

- **F2：不可配置的危险命令黑名单**
  对 `run_command`，OkCode 必须在启动 shell 子进程前使用正则识别已知高危 Windows 命令或命令组合，并直接拒绝。该黑名单不允许通过任何规则文件、权限模式或用户确认放开。黑名单至少覆盖会递归删除大范围文件、格式化磁盘、修改或清空磁盘分区、破坏系统启动配置、强制关机或重启等高破坏性操作。命中时返回明确但不泄露内部规则细节的拒绝原因。

- **F3：路径沙箱与符号链接防逃逸**
  对带有文件或目录路径参数的内置工具，OkCode 必须限制其读写和遍历目标位于启动时确定的项目目录内。检查时必须先将项目根目录和目标路径解析为规范路径，解析已有符号链接或 Windows 重解析点后再进行路径前缀判断；解析结果位于项目目录外时必须拒绝。该限制不能被规则、权限模式或用户确认放开。

- **F4：可配置的工具规则**
  OkCode 必须支持规则条目 `工具名(模式)`，例如 `Bash(git *)` 表示匹配所有以 `git ` 开头的 Bash 命令。规则结果只能是 `allow` 或 `deny`。规则中的模式必须同时支持精确匹配和 glob 匹配；匹配目标为工具名及该工具的主操作参数或路径。对 `run_command`，模式匹配完整命令文本；对文件和搜索类工具，模式匹配其规范化、相对于项目目录的路径；没有主操作参数的工具只按工具名匹配。规则的无效工具名、无效结果值或无效模式必须在加载时给出可定位的配置错误，而不是在工具执行时静默忽略。

- **F5：三层 YAML 规则来源与优先级**
  OkCode 必须从用户全局、项目级和项目本地三个 YAML 文件读取规则。用户全局规则作为默认；项目级规则覆盖用户全局；项目本地规则覆盖项目级，并且项目本地规则默认不应被版本控制提交。对同一调用，优先使用优先级最高且命中的规则；同一文件内的规则按声明顺序判断，首个命中规则生效。若高优先级来源没有命中，才继续寻找下一来源。

- **F6：会话级临时规则**
  OkCode 必须在内存中维护会话级临时规则，其优先级高于三个 YAML 来源。用户选择“本会话允许”后，后续匹配调用无需再次确认，直到 OkCode 进程退出；该规则不得写入磁盘。用户选择“本次允许”后，只允许当前这一调用，不创建可复用规则。

- **F7：整体权限模式**
  OkCode 必须支持 `strict`、`default`、`allow` 三档权限模式。权限模式用于规则未命中时的兜底处理：`strict` 直接拒绝，`default` 请求用户确认，`allow` 直接允许。权限模式不得放开危险命令黑名单、路径沙箱或任何已命中的 `deny` 规则，也不得覆盖命中的 `allow` 规则；它只处理没有明确规则结论的调用。模式的来源、默认值和当前生效值必须对用户可见。

- **F8：人在回路确认与永久规则**
  当调用未命中规则且当前模式为 `default` 时，OkCode 必须在执行前展示工具名、将要执行的命令或相对路径、以及用户可理解的风险提示，并等待用户明确选择。用户可拒绝，或选择“仅本次允许”“本会话允许”“永久允许”。“永久允许”必须将等价的 `allow` 规则写入当前项目的本地 YAML 文件；不得写入用户全局文件或项目级共享规则文件。输入中断、EOF、空输入或无法识别的选择都必须按拒绝处理。

- **F9：权限拒绝后的 Agent Loop 行为**
  黑名单拦截、路径越界、显式 `deny`、严格模式拒绝、用户拒绝和确认输入异常，都必须返回统一、结构化且可行动的工具失败结果。结果应说明调用未执行、拒绝类别和可行的下一步，但不返回敏感绝对路径或黑名单正则细节。Agent Loop 必须像处理现有工具失败一样，把该结果回灌给模型并继续迭代；除非现有的迭代上限或其他停止条件触发，不得因权限拒绝提前结束整轮。

- **F10：Windows 兼容的命令与路径表达**
  在 Windows 上，命令黑名单和规则匹配必须针对用户实际会通过 `run_command` 交给当前 shell 的命令字符串工作，不能假定 POSIX shell 语法或 Linux 文件路径。路径规则展示和匹配使用项目相对路径的正斜杠形式，接受用户输入的 Windows 路径分隔符，并在解析后统一规范化。盘符大小写、UNC 路径、盘符根目录、符号链接和目录联接造成的越界必须安全拒绝。

## 非功能需求

- **N1：纵深防御与不可绕过性**
  五层防御必须按固定安全顺序执行：危险命令黑名单、路径沙箱、会话与 YAML 规则、权限模式、人在回路。前两层和命中的 `deny` 规则均为终局拒绝，后续层不得覆盖。

- **N2：最小影响**
  未使用受保护工具的普通对话、既有工具参数校验、工具超时、工具输出截断、多工具调度、Plan Mode 与 Provider 协议适配必须保持原有行为。已被允许的工具调用继续复用现有执行实现。

- **N3：确定性与可解释性**
  对相同调用、相同规则文件、相同会话状态和相同权限模式，权限结果必须稳定。每个拒绝、允许或确认结果必须保留可用于终端展示和测试的决策来源，例如黑名单、路径沙箱、会话规则、项目规则、用户规则、模式或用户确认。

- **N4：配置安全与可维护性**
  所有 YAML 必须使用安全加载和严格字段校验。缺失的规则文件按空规则处理；存在但内容无效的文件必须阻止启动并指出文件与字段位置。项目本地规则文件必须位于项目专用隐藏目录，并在仓库的忽略规则中默认排除。

- **N5：交互安全**
  权限确认必须在终端主线程中串行完成，不能让多个工具调用同时争抢一次确认，也不能在未得到明确选择前启动相应工具。被拒绝的工具不得创建文件、修改文件或启动 shell 子进程。

- **N6：可测试性**
  黑名单匹配、Windows 风格路径和符号链接逃逸、规则解析、glob 与精确匹配、四层优先级、模式兜底、确认范围、永久规则写入及 Agent Loop 继续行为，都必须能在不执行真实危险命令、不过度依赖当前操作系统权限、也不访问真实模型服务的测试中验证。

## 不做的事

本阶段明确不包含：

- 不限制网络请求、域名、端口或 Provider API 访问。
- 不实现 CPU、内存、磁盘、进程数、命令次数或执行时间之外的资源配额。
- 不建设权限决策、命令文本、用户选择或文件变更的持久化审计日志。
- 不为第三方 MCP、远程服务或插件工具增加独立权限协议。
- 不提供图形化权限管理界面、规则编辑器或跨机器规则同步。
- 不尝试对任意 shell 脚本做完全语义分析；黑名单只负责已知高危模式，规则和确认层处理其余风险。
- 不改变项目根目录的确定方式，不允许在运行中切换项目根目录。

## 验收标准

- **AC1（覆盖 F1、N1）**：对每个内置工具发起调用时，测试可观察到统一权限决策在工具实现前完成；拒绝路径下工具替身的执行计数为零。

- **AC2（覆盖 F2）**：在 Windows 风格命令样本中，已知高危删除、格式化、分区/磁盘破坏、启动配置破坏、强制关机或重启命令均返回权限拒绝，且即使配置 `allow`、选择 `allow` 模式或用户选择允许也不会启动子进程。

- **AC3（覆盖 F3、F10）**：对项目内正常相对路径允许访问；`..`、绝对路径、UNC 路径、盘符根目录，以及通过符号链接或目录联接指向项目外的路径均返回工作区外拒绝，且读写工具未产生项目外副作用。

- **AC4（覆盖 F4）**：给定 `allow` 与 `deny` 的 `工具名(模式)` 规则，精确模式只匹配完全相同的目标，glob 模式匹配预期的命令或项目相对路径；未知工具、错误结果值、错误字段或无效模式在加载时产生明确配置错误。

- **AC5（覆盖 F5、F6）**：当用户、项目、本地和会话规则都匹配同一调用时，结果依次取会话、本地、项目、用户来源；移除更高层命中后自动回退到下一层；同一来源内首个匹配规则生效。本会话规则在进程内复用，但重启后消失。

- **AC6（覆盖 F7）**：未命中任何规则的调用在 `strict` 模式被拒绝，在 `default` 模式进入确认，在 `allow` 模式直接执行；命中 `allow` 在三种模式下均允许，命中 `deny` 在三种模式下均拒绝。

- **AC7（覆盖 F8、N5）**：`default` 模式下的未命中调用展示工具与目标信息；拒绝、空输入、EOF、无效输入都不执行工具；本次允许只放行当前调用；本会话允许在同一进程内跳过后续确认；永久允许在项目本地 YAML 写入等价规则且后续调用无需确认。

- **AC8（覆盖 F9）**：可控 Provider 连续发出一个被拒绝工具调用和一个替代工具调用时，Agent Loop 将第一个权限失败结果回灌给模型，并继续执行第二个调用或输出最终回答，不因第一次拒绝提前停止。

- **AC9（覆盖 N2、N6）**：自动化测试无需执行真实危险命令或访问真实模型服务；既有普通工具、Agent Loop、Plan Mode、Provider 序列化与终端渲染测试仍全部通过。

- **AC10（覆盖 N3、N4）**：终端或测试可见结果能识别本次决定的来源；规则文件缺失时按空规则启动，规则文件语法或结构错误时阻止启动并指出对应文件和字段位置；项目本地规则文件处于默认忽略路径。
