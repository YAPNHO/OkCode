# OkCode 第四阶段：系统提示与缓存策略 Spec

## 背景

OkCode 已经具备基础对话、工具调用、Agent Loop 和 Plan Mode 能力。当前全局指令仍然偏简单，主要解决“能调用模型干活”的问题，但还不足以稳定约束模型在真实编程任务中的行为，例如优先使用专用工具、编辑前先读取、区分规划与执行、保持安全边界和输出风格。

本阶段要把原有全局指令升级为结构化系统提示，并把稳定内容、动态环境信息和会话级补充指令分层注入。这样既能提升模型行为稳定性，也为后续项目指令文件、自动记忆、真实 MCP 接入和自动化评估留下清晰扩展点。

## 目标

- 将全局指令拆成职责明确、顺序稳定的模块，按优先级拼装成完整系统提示。
- 区分稳定提示内容与动态运行内容，让稳定内容适合走可缓存通道，动态内容通过消息通道补充。
- 在全局指令和工具描述两处强化关键工具约定，提高模型对工具选择、读写顺序和安全边界的遵守率。
- 支持运行中注入系统级补充消息，用特殊标签表达临时规则，避免被模型当成普通用户输入回复。
- 支持会话级开关的按轮次注入策略，控制完整提示、重复提示和精简提示的频率。
- 暴露缓存命中信息，能用真实 API 返回字段判断缓存策略是否生效。
- 为典型人工对比场景准备可执行的验证入口，但不在本阶段建设自动化评估体系。

## 功能需求

- **F1：固定系统提示模块**
  OkCode 必须把全局指令拆成七个固定模块，并按优先级从前到后拼装：身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出。模块之间用空行分隔，每个模块内容完整、职责单一、顺序稳定。

- **F2：环境信息追加**
  OkCode 必须在固定模块之后追加环境信息模块。环境信息用于表达当前工作区、操作系统、日期时间、可用能力或其他运行时事实。环境信息属于动态内容，不应混入稳定系统提示主体。

- **F3：可选扩展模块**
  OkCode 必须在环境信息之后支持若干可选模块，至少包括自定义指令、已激活的 Skill、长期记忆。没有对应内容时不输出空模块；有内容时按固定顺序追加，方便后续章节接入项目指令、Skill 和记忆。

- **F4：稳定内容与动态内容分层**
  OkCode 必须把稳定的全局指令和工具描述放入适合缓存的请求部分，把环境信息、会话历史、当前用户输入和运行时补充指令放入普通消息部分。动态内容变化时，不应导致稳定指令和工具描述的缓存结构失效。

- **F5：工具规则双重强化**
  OkCode 必须在全局指令中写明通用工具使用原则，并在每个工具描述中补充该工具的适用场景、优先级和关键约束。至少覆盖“优先用专用工具完成文件读取、搜索和编辑”“编辑前必须先读取或确认目标内容”“不要把代码块当作工具结果伪造”“有副作用操作要谨慎且可解释”等规则。

- **F6：系统级补充消息注入**
  OkCode 必须支持一种带特殊标签的补充指令消息，用于运行中注入临时系统级规则。该消息必须能被 Provider 序列化为系统级或等效高优先级上下文，并且文本形式上清楚标识其不是用户请求，模型不应把它当成需要直接回复的用户输入。

- **F7：任务模式按轮次注入**
  OkCode 必须支持会话级任务模式指令的注入频率控制。以规划模式为代表：首次启用时注入完整规则；之后按固定间隔重复关键规则；其余轮次只注入精简提醒。频率策略必须可测试，并且不会把模式规则永久写进普通对话历史。

- **F8：Provider 缓存命中观测**
  OkCode 必须解析 Provider 返回的缓存相关用量字段，并在现有 Token 用量事件或等效事件中暴露。没有缓存字段时必须明确标记不可用，不得估算缓存命中数量。

- **F9：人工对比场景准备**
  OkCode 必须准备一组典型场景，用于人工观察新旧提示策略的差异。场景至少覆盖读文件前置、代码搜索、文件编辑、规划模式、动态环境信息变化和缓存命中观测。本阶段只要求场景可被手工运行和记录，不要求自动评分。

## 非功能需求

- **N1：可扩展性**
  提示模块、可选模块和补充指令必须便于后续插入新模块，新增模块不应要求重写现有拼装流程。

- **N2：协议兼容性**
  OpenAI 兼容 Provider 和 Anthropic Provider 都必须继续可用。若某个协议没有原生支持完全相同的系统级消息或缓存控制能力，OkCode 必须采用该协议下最接近且可测试的表达方式，并保持统一的内部语义。

- **N3：缓存稳定性**
  稳定提示内容和工具描述的文本顺序、空行、标题和工具声明顺序必须保持可预测。只有真实指令内容变化时，才应改变可缓存内容。

- **N4：行为稳定性**
  普通对话、已有工具调用、Agent Loop、多工具调度和 Plan Mode 的既有成功路径必须保持可用。提示系统升级不能改变工具执行器的安全分类和并发/串行规则。

- **N5：可测试性**
  系统提示拼装、模块顺序、动态消息注入、任务模式注入频率、工具描述强化和缓存字段解析都必须能在不访问真实模型服务的情况下通过单元测试或可控 Provider 测试验证。

- **N6：输出可理解性**
  用户可见输出仍然使用简体中文，保持当前终端风格，不暴露原始系统提示全文、API Key 或不必要的 Provider 请求细节。

## 不做的事

本阶段明确不包含：

- 不加载项目级指令文件，例如仓库内新的项目规则文件或多层目录规则。
- 不实现自动记忆提取、长期记忆写入、记忆检索或记忆压缩。
- 不接入真实 MCP 工具或外部工具市场。
- 不建设自动化评估平台、打分器、批量回归报告或模型间统计评测。
- 不实现用户可编辑的复杂提示模板语言。
- 不改变现有工具执行器的权限模型、沙箱策略或并发调度策略。
- 不引入多 Agent 协作、后台任务调度或跨会话持久化。

## 验收标准

- **AC1（覆盖 F1、F2）**：构造完整系统提示时，输出按“身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出、环境信息”的顺序排列，模块之间空行分隔，且环境信息不出现在前七个固定模块中。

- **AC2（覆盖 F3）**：分别提供自定义指令、已激活 Skill 和长期记忆内容时，系统提示在环境信息之后按固定顺序追加对应模块；未提供内容时不出现空标题或占位符。

- **AC3（覆盖 F4、N3）**：连续两轮只改变当前时间、工作区状态或用户输入时，可缓存的稳定提示内容和工具描述保持字节级一致；修改固定模块文本时，可缓存内容发生变化。

- **AC4（覆盖 F5）**：检查模型可见的全局指令和工具描述，能同时看到“优先使用专用工具”“编辑前先读或确认目标内容”“不要伪造工具结果”“副作用操作要谨慎”的规则；每条规则至少在全局指令和一个相关工具描述中出现。

- **AC5（覆盖 F6、N2）**：给定一条运行时补充指令，Provider 请求中能看到该补充指令以系统级或等效高优先级上下文出现，并带有特殊标签；该补充消息不以普通用户提问形式进入历史。

- **AC6（覆盖 F7）**：启用规划模式后，第 1 轮注入完整规则，第一个配置的重复轮次再次注入关键规则，其他轮次只注入精简提醒；关闭规划模式后不再注入规划规则。

- **AC7（覆盖 F8）**：当测试 Provider 返回缓存命中字段时，OkCode 的用量事件包含真实缓存命中信息；当字段缺失时，用量事件明确显示缓存信息不可用且不填估算值。

- **AC8（覆盖 F9）**：人工对比场景文档或脚本覆盖读文件前置、代码搜索、文件编辑、规划模式、动态环境变化和缓存观测六类场景，并说明每个场景要观察的新旧差异。

- **AC9（覆盖 N4、N5）**：不访问真实模型服务的自动化测试通过，且既有普通对话、工具调用、Agent Loop 和 Plan Mode 测试仍然通过。

- **AC10（覆盖 N6）**：运行过程中用户可见输出仍为简体中文；错误、欢迎信息、用量信息和调试摘要中不泄露 API Key，也不默认打印完整系统提示。
