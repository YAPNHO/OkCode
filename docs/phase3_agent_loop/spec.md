# OkCode 第三阶段：Agent Loop Spec

## 背景

第二阶段已经让 OkCode 具备工具调用和结果回写能力：模型可以请求本地工具，OkCode 执行工具后把结构化结果写回会话历史。但当前能力仍停留在“一步一停”：每次用户输入最多执行一次工具调用，工具结果返回后不会自动继续请求模型，也不会基于结果继续调整方案。

因此，OkCode 还不能像真正的编程 Agent 一样自主完成多步骤任务。本阶段要在已有工具系统之上加入 Agent Loop，让一次用户任务能够持续经历“模型推理 -> 工具调用 -> 结果回写 -> 继续推理”的循环，直到模型给出最终答复或触发明确停止条件。

## 目标

- 让 OkCode 在一次普通任务中自动执行 ReAct 风格循环，能基于工具结果继续判断、调整和推进任务。
- 提供一套异步事件流，把 Agent 运行时和终端界面解耦，使界面只负责消费事件和展示状态。
- 支持流式收集的双路行为：一边实时输出文本增量，一边保存完整助手回复供后续判断。
- 支持模型一次返回多个工具调用，并按工具安全类别分批执行：只读工具可并发，有副作用工具串行。
- 支持 Plan Mode 两段式工作流：`/plan` 只允许读类工具先生成计划，`/do` 默认执行当前会话最近一次成功保存的计划。
- 提供多种停止条件，默认最大模型迭代次数为 12，连续未知工具调用停止阈值为 2。

## 功能需求

- **F1：ReAct 循环**  
  每个普通任务都执行循环式运行流程。模型完成一轮回复后，如果包含工具调用，OkCode 执行工具、把该轮助手回复和工具结果加入本轮临时上下文，再发起下一轮模型调用；如果模型返回不含工具调用的非空正式文本，则任务成功结束。

- **F2：流式双路收集**  
  模型流式输出时，文本增量必须立即以事件形式发给界面；流结束后，OkCode 必须得到完整助手回复，用于工具调度、历史回写和停止判断。思考文本与正式答复必须保持可区分。

- **F3：异步事件流**  
  Agent 对外只输出异步事件流。事件至少覆盖文本增量、工具调用、工具执行结果、每轮 Token 用量和进度。每轮模型请求结束后都应产生 Token 用量事件；如果服务端无法提供精确用量，应明确标记为不可用，不得伪造数值。

- **F4：多工具调用与分批执行**  
  模型一次返回多个工具调用时，OkCode 按模型给出的原始顺序划分执行批次。连续只读工具可并发执行；写文件、编辑文件和执行命令均视为有副作用调用，必须逐个串行执行。每个工具调用都产生独立结果，并按原始调用顺序回写临时上下文。

- **F5：Plan Mode 两段式**  
  用户输入 `/plan <任务>` 时，模型只能看到读文件、找文件、搜代码三类只读工具，并在成功结束后把最终文本保存为当前会话的最近计划。用户输入 `/do` 时，OkCode 默认使用当前会话最近一次成功保存的计划，并在全量工具可用的模式下执行。没有已保存计划时，OkCode 必须显示明确提示且不请求模型。

- **F6：停止条件**  
  满足任一条件即停止本轮任务：模型给出最终文本、达到 12 次模型迭代、用户取消、连续 2 次工具结果为未知工具，或模型流异常。除模型给出最终文本外，停止后不得继续请求模型。

- **F7：历史提交语义**  
  本轮运行过程中只维护临时对话上下文。只有成功得到最终文本时，才把用户消息、各轮助手消息和工具结果一次性写入会话历史。取消、流异常、达到迭代上限和连续未知工具停止时，均不保存本轮历史；已经执行工具产生的外部副作用不回滚。

## 非功能需求

- **N1：协议兼容性**  
  继续兼容 OpenAI 与 Anthropic 两套流式协议；两者都必须能表达同一轮的多个工具调用，并在后续模型请求中保留正确的调用与结果对应关系。

- **N2：运行稳定性**  
  取消、工具失败、未知工具、流异常和达到迭代上限都只结束当前任务，不得导致 REPL、会话对象或 Provider 客户端不可继续使用。

- **N3：顺序稳定性**  
  工具批次的结果回写顺序必须与模型给出的调用顺序一致；并发只影响只读工具的执行耗时，不改变结果顺序。

- **N4：界面解耦**  
  终端界面只消费事件，不直接参与模型调用、工具调度、计划保存或停止判断。

- **N5：可测试性**  
  核心循环、停止条件、并发批次、计划模式和协议历史，都必须能在不访问真实模型服务、不执行真实副作用命令的条件下自动测试。

- **N6：向后兼容性**  
  普通文本对话、已有的单工具调用流程和既有终端展示行为必须保持可用。

## 不做的事

本阶段明确不包含：

- 工具权限系统、命令白名单、沙箱隔离和用户交互式确认。
- 上下文压缩、工具结果摘要、跨会话记忆和计划持久化到磁盘。
- 自动重试模型请求、模型降级、断点续跑和停止后继续执行。
- 根据参数或数据依赖自动重排工具调用；本阶段仅按调用顺序和工具安全类别分批。
- 新增 Git、网络、目录删除、文件移动或多模态工具。
- 除 `/plan`、`/do` 外的命令体系、交互式计划编辑或多 Agent 协作。

## 验收标准

- **AC1（覆盖 F1、F7）**：通过可控 Provider 驱动“工具调用 -> 工具结果 -> 再次工具调用 -> 最终文本”的脚本流程，OkCode 自动完成多轮循环，且只在最终文本产生后提交完整历史。
- **AC2（覆盖 F2）**：流式文本到达时，界面可先收到文本事件；流结束后，完整回复可正确识别多个工具调用并用于后续调度。
- **AC3（覆盖 F3、N4）**：一次任务的事件流包含文本、工具调用、工具结果、每轮 Token 用量和进度；界面替换为测试订阅方后，运行结果不变。
- **AC4（覆盖 F4、N3）**：同一轮中多个连续只读工具可观测到并发执行；写文件、编辑文件和执行命令始终按原顺序逐个执行；结果回写顺序与模型调用顺序一致。
- **AC5（覆盖 F6）**：模型返回无工具调用的正式文本时，任务成功结束；连续工具调用场景中最多发起 12 次模型请求，且不发起第 13 次。
- **AC6（覆盖 F6、F7、N2）**：取消、流异常、连续两次未知工具、达到迭代上限时均停止当前任务、不再请求模型、不提交本轮历史，并可继续接收下一条用户输入。
- **AC7（覆盖 F5）**：`/plan` 请求中模型只能看到三类只读工具，成功后保存最终计划；`/do` 使用该计划并向模型暴露全量工具；不存在已保存计划时不请求模型且显示明确提示。
- **AC8（覆盖 N1）**：OpenAI 与 Anthropic 的可控流测试均覆盖单轮多个工具调用及其结果回写，下一轮请求中的调用标识、工具名称、参数和结果一一对应。
- **AC9（覆盖 F1、F5）**：端到端脚本覆盖“`/plan` 调研并保存计划 -> `/do` 执行计划 -> 多轮工具调用 -> 最终答复”的完整链路。
- **AC10（覆盖 N5、N6）**：不访问真实模型服务、不执行真实副作用命令的情况下，完整自动化测试套件通过，并确认普通文本对话与既有单工具调用流程仍可用。
