# OkCode 第十二阶段：子 Agent 委派执行 Spec

## 背景

OkCode 已具备主 Agent 循环、本地工具系统、权限系统、上下文管理、MCP、命令系统、Skill 机制和 Hooks 机制。第十一阶段已经允许 Hook YAML 声明“子 Agent 动作”并完成占位校验，但运行时不会真实启动子 Agent。

当前主 Agent 执行复杂任务时，所有探索、工具结果、临时假设和中间推理都会进入同一条会话历史。即使已有上下文压缩机制，长期任务仍容易出现上下文污染：主 Agent 需要记住太多细枝末节，子任务之间也可能互相干扰。同时，某些工作天然适合交给独立执行单元，例如代码搜索、局部诊断、文档整理、测试验证或固定角色审查。

本阶段为 OkCode 增加子 Agent 委派能力：主 Agent 通过一个稳定的 Agent 工具启动独立子 Agent。子 Agent 可以按预定义角色从空白上下文开始，也可以从父对话 Fork 出来继承历史和工具集。子 Agent 运行时状态与主对话隔离，完成后通过后台任务结果异步回到主对话，从而降低上下文污染，并为后续多 Agent 编排打基础。

## 目标

- 提供一个统一且稳定的 Agent 工具入口，让模型通过类型参数选择“定义式子 Agent”或“Fork 式子 Agent”。
- 支持用 Markdown 加 YAML frontmatter 定义可复用角色，并按多来源优先级加载和覆盖。
- 让定义式子 Agent 从空白对话和固定角色提示启动，适合审查、搜索、总结等专门职责。
- 让 Fork 式子 Agent 继承父对话历史和工具集，并尽量复用提示缓存以降低首次请求成本。
- 隔离子 Agent 的消息、权限、文件读缓存、Token 计数和运行状态，同时共享底层基础设施。
- 子 Agent 以非交互“跑到底”模式执行，并把最终结果、状态和用量异步送回主对话。
- 通过多层工具过滤和后台白名单防止危险工具扩散、无限嵌套和不受控后台执行。
- 提供后台任务管理能力，追踪子 Agent 状态、结果、错误和用量，并支持多种进入后台方式。

## 功能需求

- **F1：统一 Agent 工具入口**
  OkCode 必须向主 Agent 暴露一个稳定的 Agent 工具。该工具的参数必须能区分“定义式子 Agent”和“Fork 式子 Agent”两条执行路径，但工具本身的名称、描述和参数结构必须保持稳定，不能因为加载了多少角色而改变工具列表。

- **F2：定义式子 Agent 启动**
  当主 Agent 请求定义式子 Agent 时，OkCode 必须按角色名解析一个预定义角色。子 Agent 从空白对话开始，只携带角色系统提示、用户交给它的任务、可用工具过滤结果和必要运行环境。它不得继承父对话历史，除非父任务显式把内容作为输入传给它。

- **F3：Fork 式子 Agent 启动**
  当主 Agent 请求 Fork 式子 Agent 时，OkCode 必须从当前父对话创建隔离快照。该快照包含父对话已有消息、当前运行模式和父 Agent 可用工具集合。Fork 式子 Agent 的第一次模型请求应尽量沿用父对话前缀，使支持提示缓存的 Provider 能命中缓存；Fork 式子 Agent 必须强制进入后台执行。

- **F4：角色定义格式**
  角色定义必须使用 Markdown 文件表示。文件开头使用 YAML frontmatter 声明元数据，正文作为子 Agent 生命周期内持续生效的系统提示。元数据至少支持角色名、用途说明、工具白名单、工具黑名单、模型策略、最大轮次和权限模式。

- **F5：角色多来源加载与覆盖**
  OkCode 必须从插件级、内置级、用户级和项目级来源加载角色定义。同名角色按优先级覆盖：项目级高于用户级，用户级高于内置级，内置级高于插件级。加载结果必须可诊断：用户能知道某个角色最终来自哪里，以及哪些低优先级角色被覆盖。

- **F6：角色配置校验**
  角色加载阶段必须校验 frontmatter。缺少必填字段、未知字段、非法模型策略、非法权限模式、白名单和黑名单同时产生不可解释冲突、最大轮次不是正整数、正文为空等情况，都必须给出可定位错误。错误信息至少包含来源文件、角色名或候选角色名、字段名和失败原因。

- **F7：模型与最大轮次**
  子 Agent 必须支持继承父 Agent 模型，也必须支持角色指定模型档位。模型档位只允许使用 OkCode 已知且当前配置可解析的选项。最大轮次用于限制子 Agent 连续模型调用次数；达到最大轮次仍未自然完成时，子 Agent 必须停止并返回明确的未完成状态和已有观察结果。

- **F8：权限模式隔离**
  每个子 Agent 必须拥有独立权限状态。角色可以指定权限模式；未指定时继承父对话当前权限模式。子 Agent 内发生的一次性允许、会话允许、拒绝记录或权限统计不得写回父 Agent 的权限状态。全局禁止规则必须始终生效，不能被角色权限模式绕过。

- **F9：运行时状态隔离**
  子 Agent 的消息历史、Token 计数、文件读缓存、工具调用记录、上下文压缩状态、后台任务状态和错误状态必须与父 Agent 以及其他子 Agent 隔离。任意子 Agent 的压缩、失败、取消或达到轮次上限，都不得破坏父对话历史和其他任务状态。

- **F10：基础设施共享**
  子 Agent 可以共享底层 LLM 客户端、Provider 配置、Hook 引擎、工具实现、文件系统访问入口、MCP 管理器和日志设施。共享的是无会话状态或可安全复用的基础设施；任何会话相关、权限相关、缓存相关和用量相关状态必须按子 Agent 实例隔离。

- **F11：非交互跑到底模式**
  子 Agent 必须以非交互模式运行。启动后它持续执行模型请求和工具调用，直到模型不再请求工具、达到最大轮次、被取消、超时、权限拒绝导致无法继续、Provider 出错或工具系统返回不可恢复错误。子 Agent 不得直接向终端发起交互式提问；需要用户输入时必须把阻塞原因作为结果返回给主对话。

- **F12：完成判定**
  当子 Agent 的模型响应没有新的工具调用时，OkCode 必须将该响应视为子 Agent 的自然完成。完成结果至少包含最终文本、完成状态、轮次数、工具调用摘要、Token 用量和必要的错误或警告信息。

- **F13：异步结果通知**
  子 Agent 结束后，后台任务管理器必须把结果异步送回主对话。主 Agent 下一次可见上下文应能看到任务完成通知、任务标识、子 Agent 类型、角色名或 Fork 标识、最终摘要、状态、错误信息和用量。通知不得伪造成用户消息，也不得破坏已有工具调用与工具结果配对。

- **F14：后台任务管理**
  OkCode 必须提供后台任务管理器追踪子 Agent 任务。每个任务至少有稳定标识、来源主对话、类型、角色或 Fork 信息、创建时间、开始时间、结束时间、当前状态、结果摘要、完整结果引用、错误信息、轮次数、工具调用数和 Token 用量。

- **F15：进入后台的方式**
  子 Agent 必须支持三种进入后台方式：主 Agent 显式指定后台执行；前台执行超过配置阈值后自动切到后台；用户手动把正在运行的子 Agent 切到后台。Fork 式子 Agent 必须始终后台执行，不能以前台阻塞方式运行。

- **F16：前台与后台状态转换**
  定义式子 Agent 可以以前台或后台启动。前台模式必须在短任务完成时直接把工具结果返回给主 Agent；切到后台后必须立即返回任务标识和当前状态，后续完成时再异步通知。状态转换必须是幂等的，重复切后台不得创建重复任务。

- **F17：工具过滤多层防线**
  子 Agent 可用工具必须经过多层过滤。过滤顺序至少包括全局禁止工具、后台允许工具集合、父 Agent 工具集合、角色白名单和角色黑名单。任何一层拒绝后该工具都不得出现在子 Agent 工具列表中。过滤结果为空时，子 Agent 仍可运行纯文本任务，但必须在结果中说明没有可用工具。

- **F18：防止无限嵌套**
  OkCode 必须防止子 Agent 不受控地继续创建子 Agent。默认情况下，子 Agent 不得调用 Agent 工具；只有显式安全配置允许时才能开放受限嵌套。即使开放嵌套，也必须有最大深度或等价限制，并且后台白名单必须继续生效。

- **F19：权限和工具拒绝可观测**
  当子 Agent 因工具过滤、权限模式、全局禁止、后台白名单、最大深度或用户拒绝导致工具不可用或调用失败时，失败必须作为结构化结果进入子 Agent 历史，并最终能被主对话看到。模型必须能据此调整任务或解释无法完成的原因。

- **F20：取消与超时**
  后台任务管理器必须支持取消正在运行的子 Agent。任务级超时触发时，子 Agent 必须停止后续模型请求和工具调用，释放可释放资源，并返回超时状态、已完成工作摘要和已产生用量。

- **F21：用量统计**
  子 Agent 必须独立统计模型用量和工具调用数量。主 Agent 能看到每个子 Agent 的用量汇总；父对话的用量展示可以汇总子 Agent 用量，但必须能区分父 Agent 自身用量和子 Agent 用量。

- **F22：与 Hook 子 Agent 动作对接**
  Hooks 中已有的子 Agent 动作占位必须能对接本阶段真实运行能力。Hook 触发子 Agent 时必须走同一套角色解析、工具过滤、后台任务管理、权限隔离和结果记录机制。非拦截 Hook 触发的子 Agent 默认进入后台。

- **F23：用户可见任务查询**
  OkCode 必须提供用户可见方式查询后台任务状态。查询结果至少展示任务标识、类型、角色或 Fork 标识、状态、开始时间或等待时长、轮次数、工具调用数、用量和结果摘要。没有后台任务时必须显示明确空状态。

## 非功能需求

- **N1：主流程兼容**
  未调用 Agent 工具、未配置角色、未触发 Hook 子 Agent 动作时，OkCode 的普通对话、命令系统、权限系统、上下文管理、MCP、Skill 激活、Hooks 和会话持久化行为必须保持不变。

- **N2：安全优先**
  子 Agent 不得绕过现有工作区约束、权限规则、全局禁止命令、工具参数校验和 Hook 拦截。后台任务不得悄悄执行需要交互确认的高风险操作；无法确认时必须拒绝或返回阻塞状态。

- **N3：上下文可控**
  子 Agent 的内部消息默认不完整注入父对话。父对话只接收必要通知、摘要和可追踪引用，避免把子 Agent 的全过程再次污染主上下文。

- **N4：提示缓存友好**
  Fork 式子 Agent 应尽量保持父对话前缀稳定，避免无必要地重写、重排或插入会破坏缓存命中的消息。缓存命中不是硬性保证，但实现不得主动破坏可复用前缀。

- **N5：可观测性**
  子 Agent 创建、启动、工具过滤、权限拒绝、后台切换、取消、超时、自然完成、失败、结果通知和用量汇总都必须有可测试或可日志化事件。

- **N6：测试友好**
  子 Agent 主流程必须能用无网络模型替身、假工具和假权限确认器确定性测试。测试不得依赖真实模型服务、真实外网或危险命令。

- **N7：资源边界**
  子 Agent 必须有最大轮次、任务超时或等价保护，后台任务管理器必须避免已完成任务无限增长。任务结果可以保留完整引用，但主对话注入内容必须有长度边界。

- **N8：失败隔离**
  单个子 Agent 启动失败、运行失败、取消、超时、角色加载失败或结果通知失败，不得导致父 Agent 会话崩溃。父 Agent 必须收到可行动的错误说明。

## 不做的事

本阶段明确不包含：

- 不实现 Worktree 文件隔离、每个子 Agent 独立工作区副本或跨分支文件沙箱。
- 不实现多 Agent 团队编排、复杂任务图、Agent 间互发消息或协作调度。
- 不实现后台任务的跨会话、跨进程或重启后持久化恢复。
- 不实现图形化后台任务面板。
- 不实现分布式执行、远程 Worker、进程池或多机器调度。
- 不实现子 Agent 对用户的交互式追问；需要用户决策时返回主对话处理。
- 不把角色定义做成 Skill 的替代品；角色只描述子 Agent 身份、约束和工作风格。
- 不保证所有 Provider 都能实际命中提示缓存；只要求 Fork 路径保持缓存友好的消息前缀。
- 不改变现有工具的业务语义、权限规则语义或 Hook 条件语义。

## 验收标准

- **AC1（覆盖 F1）**：主 Agent 的工具列表中出现一个稳定的 Agent 工具；新增、删除或覆盖角色定义后，该工具列表不因角色数量变化而变化；工具参数能分别启动定义式和 Fork 式路径。

- **AC2（覆盖 F2、F4、F5、F6）**：给定合法角色文件，定义式子 Agent 从空白对话和角色正文启动；给定插件级、内置级、用户级、项目级同名角色，最终使用最高优先级版本并能展示来源；给定非法 frontmatter，加载阶段报出包含文件、角色和字段的错误。

- **AC3（覆盖 F3、N4）**：Fork 式子 Agent 创建时包含父对话历史和父可用工具集合，并强制返回后台任务标识；测试能观察到 Fork 首次请求使用父对话前缀顺序，不插入会破坏前缀稳定性的额外消息。

- **AC4（覆盖 F7、F11、F12）**：子 Agent 在模型不再请求工具时自然完成；达到最大轮次时停止并返回未完成状态；完成结果包含最终文本、状态、轮次数、工具调用摘要和用量。

- **AC5（覆盖 F8、F9、F10、N8）**：子 Agent 内的一次性允许或会话允许不会写回父 Agent；子 Agent 压缩、失败或取消不会改变父对话历史；共享 LLM 客户端和 Hook 引擎时，各子 Agent 的消息、权限、缓存和用量仍相互隔离。

- **AC6（覆盖 F13、N3）**：后台子 Agent 完成后，主对话收到异步通知；通知包含任务标识、类型、角色或 Fork 标识、状态、摘要、错误和用量；通知不是用户消息，也不会破坏工具调用与工具结果配对。

- **AC7（覆盖 F14、F15、F16、F20、F23）**：后台任务管理器能展示运行中、完成、失败、取消和超时状态；显式后台、超时自动切后台、手动切后台都能产生同一个可查询任务；重复切后台不会创建重复任务；取消和超时都会停止后续执行并保留已有摘要。

- **AC8（覆盖 F17、F18、F19、N2）**：子 Agent 工具列表按全局禁止、后台白名单、父工具集合、角色白名单和角色黑名单过滤；默认情况下子 Agent 不能再调用 Agent 工具；被过滤或权限拒绝的工具调用以结构化失败结果返回，并能被主对话看到。

- **AC9（覆盖 F21）**：每个子 Agent 都独立统计模型用量和工具调用数；主 Agent 的用量展示能区分父 Agent 自身用量和子 Agent 用量，并能按任务查看汇总。

- **AC10（覆盖 F22）**：Hook 子 Agent 动作命中时不再只记录占位跳过，而是走真实子 Agent 启动路径；非拦截 Hook 触发的子 Agent 默认进入后台，并能在任务查询中看到。

- **AC11（覆盖 N1、N5、N6、N7）**：未使用子 Agent 时现有测试保持通过；新增测试使用无网络替身覆盖创建、角色加载、Fork、工具过滤、权限隔离、后台切换、取消、超时、结果通知和用量统计；主对话注入的子 Agent 结果有明确长度边界。
