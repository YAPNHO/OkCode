# OkCode 第九阶段：命令注册与分发机制 Spec

## 背景

OkCode 当前已经有若干斜杠命令能力，但识别逻辑分散在交互入口和会话执行流程中：应用入口提前处理退出和恢复，会话流程直接识别权限、压缩、规划和执行相关输入。随着本地操作、界面状态、运行时模式和提示词类命令继续增加，继续用分支判断会让命令元数据、帮助信息、补全、别名和行为边界逐渐失控。

本阶段要把“用户输入以斜杠开头时绕过普通 Agent 对话”的规则显式化：常用本地操作必须响应快、少消耗 Token、行为确定；需要交给 AI 的命令也必须先由命令系统识别，再按预设方式把用户意图送入对话。

## 目标

- 建立统一的命令注册、解析、分发和补全机制。
- 让纯本地命令、影响界面类命令、提示词类命令有清晰的执行边界。
- 保留现有上下文压缩、会话恢复、计划/执行流程和退出控制等用户可见语义。
- 让帮助、别名、用法、参数提示和隐藏属性由同一份命令元数据驱动。
- 为后续 Skill 系统的用户自定义命令留下扩展位置，但本阶段不实现动态扩展。

## 功能需求

- **F1：命令注册中心**  
  系统启动时集中登记内置命令的名称、别名、简短描述、用法示例、命令类型、参数提示、是否隐藏和处理入口。命令名称和别名统一按大小写不敏感规则归一。任一命令名、别名或别名之间发生冲突时，启动必须失败并给出可定位的冲突信息，不能等到用户输入时才失败。

- **F2：斜杠输入解析**  
  用户输入为空或只包含空白时立即返回，不触发命令也不触发 Agent。非斜杠输入按普通用户消息处理。斜杠输入中，第一个空格前的片段是命令名，后续原文是参数；命令名去掉前导斜杠并转小写，参数保留用户输入的正文语义。未命中命令时，系统显示未知命令提示，并引导用户使用帮助命令查看可用命令。

- **F3：执行模式分类**  
  每条命令必须声明一种命令类型：  
  1. 纯本地类：只读取或展示本地状态，不调用 Provider，不写入普通对话历史。  
  2. 影响界面类：影响 TUI 生命周期、当前会话边界、运行时模式、状态栏或可见界面，不直接把斜杠输入写入普通对话历史。  
  3. 提示词类：由命令系统识别后，把固定提示词或既有执行指令文本注入对话，并立即触发一个普通回合。

- **F4：运行时模式与状态栏**  
  系统支持默认模式和计划模式两种运行时模式。默认模式状态栏显示 [DEFAULT]；计划模式状态栏显示 [PLAN]。本阶段的“运行时模式”用于控制后续回合的工具可见范围和提示注入，不等同于现有工具权限规则文件中的 strict/default/allow 策略。

- **F5：用户回车入口分流**  
  用户回车后先进入统一分流器。分流器判断输入是否为命令：命令输入走命令解析和分发，非命令输入才进入普通 Agent 对话。纯本地和影响界面类命令不得把原始斜杠输入送给模型；提示词类命令只有在命令处理明确产生注入消息时才进入对话。

- **F6：补全与隐藏命令**  
  斜杠命令支持 Tab 补全。没有匹配时不补全；只有一个可见匹配时直接补全；多个可见匹配时展示候选菜单。隐藏命令仍可被直接执行，但不出现在帮助列表和补全候选中。

- **F7：帮助输出**  
  帮助命令按命令名字典序输出已注册的非隐藏命令，每行展示“命令名字 + 一句描述”两列对齐列表。帮助输出必须来自注册中心元数据，不能维护另一份手写列表。

- **F8：内置十二条命令**  
  本阶段内置以下十二条命令，并统一进入注册中心：  
  /exit：影响界面类，关闭 TUI 进程，沿用现有清理与退出路径。  
  /plan：影响界面类，切换运行时模式到计划模式，状态栏显示 [PLAN]，不立即触发模型回合。  
  /do：提示词类，先把运行时模式切回默认模式，再向对话注入现有的执行指令文本，并立即触发回合；外部行为与本 spec 实施前一致。  
  /compact：影响界面类，手动触发上下文压缩，沿用既有摘要约束和失败熔断路径。  
  /resume：影响界面类，打开历史会话列表，选中后从该会话最后一个 compact 标记之后恢复，沿用之前的所有恢复约束。  
  /clear：影响界面类，关闭当前会话存档文件，开启新会话存档文件，清空当前内存中的消息列表，把会话累计 Token 计数与回合数归零；执行后向用户输出 notice，提示已结束当前会话并开启新会话。  
  /help：纯本地类，按命令名字典序输出每条已注册非隐藏命令的“名字 + 一句描述”两列对齐列表。  
  /status：纯本地类，输出当前运行时模式、累计 Token 输入/输出、可用工具数量、已加载记忆条目数、当前模型名、当前工作目录六项信息。  
  /memory：纯本地类，输出当前已加载的项目层与用户层记忆文件名列表，只列文件名，不展开内容。  
  /permission：纯本地类，输出当前运行时模式的字符串名称，与 /status 中相同的字符串形式。  
  /session：纯本地类，输出当前会话的标识信息，至少包含当前会话存档文件路径与 session 标识。  
  /review：提示词类，向对话注入一条固定文本的代码审查请求消息，并立即触发回合；命令处理器不读 git diff、不收集任何外部上下文。

- **F9：/review 固定提示词**  
  /review 注入的消息必须是固定文本：  
  Please review the current git diff for code changes. Focus on:
  1. Logic errors
  2. Security issues
  3. Performance problems
  4. Code style

- **F10：会话边界与累计计数**  
  系统需要维护当前会话的 session 标识、存档文件路径、内存消息列表、累计输入 Token、累计输出 Token 和回合数。/clear 必须开启新的会话边界并归零这些累计值，但不得删除已关闭的历史会话存档文件。

## 非功能需求

- **N1：确定性与低延迟**  
  纯本地和影响界面类命令必须同步或近实时完成，不发起普通 Agent 模型请求。命令解析、注册冲突检查、帮助和补全必须可用无网络测试确定性验证。

- **N2：启动期失败优先**  
  命令注册元数据错误、名称冲突、别名冲突、缺失处理入口或非法命令类型必须在启动或命令中心构造阶段暴露，不能隐藏到运行时。

- **N3：渲染解耦**  
  命令处理只依赖抽象界面能力和会话能力，不直接依赖具体终端库、控制台对象或底层输入控件，保证后续替换 TUI 框架时命令层不用重写。

- **N4：历史原子性**  
  纯本地和影响界面类命令不得把原始斜杠输入写入普通对话历史。提示词类命令进入对话时，应沿用现有会话原子提交规则：只有完整成功的用户/助手/工具消息才正式进入历史，取消、异常或失败时不得留下半提交状态。

- **N5：可测试性**  
  命令注册、解析、别名、补全、未知命令、帮助输出、模式切换、状态栏标记、提示词命令转交、/clear 会话重置和既有命令迁移都必须有自动化测试覆盖。涉及 Provider 的命令必须使用可控替身，不依赖真实网络。

- **N6：Windows 兼容性**  
  命令行为、清屏、状态显示和路径展示必须适配 OkCode 的 Windows 运行环境，不假设 Unix 专属终端能力。

## 不做的事

- 不实现用户自定义命令、项目级自定义命令或配置文件驱动的命令扩展。
- 不实现动态生成提示词；提示词类命令只使用代码内置固定文本或既有执行指令文本。
- 不实现命令级权限控制；本阶段沿用现有工具权限系统，不额外为命令建立授权层。
- 不引入 Skill 系统，也不把命令注册中心设计成可热插拔插件系统。
- 不实现跨进程命令状态同步、远程命令执行或后台任务调度。
- 不改变工具调用权限、MCP 工具发现、上下文压缩阈值、Provider 请求协议或模型参数。
- /clear 不删除历史会话存档文件，只关闭当前存档并开启新会话。
- /review 命令处理器不读取 git diff、不调用工具、不预先收集文件或版本控制上下文。

## 验收标准

- **AC1：注册冲突提前失败**  
  构造命令中心时，如果两个命令共用同一名称、同一别名，或某个别名撞到另一个命令名，启动阶段失败并指出冲突键和冲突命令；无冲突时十二条内置命令可被查询。

- **AC2：解析规则正确**  
  输入空白字符串时不产生命令结果也不进入 Agent；输入 hello 进入普通 Agent；输入 /STATUS now 命中 status 命令且参数为 now；输入未知命令时显示帮助引导且不调用 Provider。

- **AC3：帮助输出正确**  
  执行 /help 时，输出按命令名字典序排序，只展示命令名字和一句描述两列；帮助内容来自注册中心元数据。

- **AC4：本地状态命令不消耗模型**  
  执行 /help、/status、/memory、/permission、/session 时，不调用 Provider，不写普通对话历史，并输出对应本地状态。

- **AC5：模式切换正确**  
  启动默认显示 [DEFAULT]；执行 /plan 后运行时模式变为 plan 且状态栏显示 [PLAN]；执行 /do 时先切回 default，再按既有执行指令立即触发回合。

- **AC6：/do 兼容旧外部行为**  
  当前会话存在已保存计划时，执行 /do 后注入与本 spec 实施前一致的执行计划消息并触发 Provider；没有已保存计划时，显示既有“没有可执行的计划”提示，不触发 Provider。

- **AC7：/compact 与 /resume 兼容旧约束**  
  /compact 仍可手动触发上下文压缩并沿用摘要失败熔断；/resume 打开历史会话列表，选择后从最后一个 compact 标记之后恢复，并保留既有损坏记录跳过、工具边界截断和超预算压缩约束。

- **AC8：/clear 建立新会话边界**  
  执行 /clear 后，旧会话存档文件不删除但停止写入；系统创建新的 session 标识和存档文件；当前内存消息列表、累计输入/输出 Token 和回合数归零；终端显示已结束当前会话并开启新会话的 notice。

- **AC9：/status 输出六项信息**  
  /status 输出当前运行时模式、累计 Token 输入/输出、可用工具数量、已加载记忆条目数、当前模型名、当前工作目录六项信息，且 /permission 输出的模式字符串与 /status 中一致。

- **AC10：/memory 和 /session 输出范围正确**  
  /memory 只列当前已加载的项目层与用户层记忆文件名，不展开内容；/session 至少输出当前会话存档文件路径与 session 标识。

- **AC11：/review 固定注入**  
  执行 /review 时，命令层不读取 git diff、不收集外部上下文，只向对话注入固定代码审查请求文本并立即触发回合。

- **AC12：完整回归验证**  
  命令相关新增测试通过；现有普通对话、计划/执行提示注入、上下文压缩、权限系统、会话恢复、终端渲染、工具执行和 MCP 相关测试保持通过；静态检查保持通过。
