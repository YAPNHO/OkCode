# OkCode 第七阶段：上下文管理 Spec

## 背景

OkCode 当前会在每次模型请求中携带已提交的完整会话历史。工具执行结果会以工具消息进入历史，通常是上下文增长的主要来源；现有 Token Usage 仅用于展示，尚未参与预算控制。因此，长时间执行任务时会因输入上下文累积而接近模型窗口上限。

本阶段为会话增加两层上下文管理：先外置过大的工具结果，减少单条消息造成的尖峰；再在总历史逼近窗口时将较早消息压缩为结构化摘要，同时保留最近原文和可重新读取的原始文件。

## 目标

- 在固定 `200_000` Token 上下文窗口内支持长时间 Agent 工作。
- 优先压缩工具结果，避免改写用户原始消息。
- 自动保护上下文窗口，并允许用户随时主动压缩。
- 压缩后保留可追溯文件路径、最近原文和明确的回读边界，避免模型根据摘要臆测代码细节。

## 功能需求

- **F1：请求前预算检查**  
  每次正常 API 请求前依次执行轻量预防和重量兜底。上下文窗口固定为 `200_000` Token；估算完整输入超过 `167_000` Token 时自动触发全量摘要，为摘要输出预留 `20_000` Token，并预留 `13_000` Token 处理估算误差。

- **F2：单个工具结果外置**  
  单个工具结果超过 `50_000` 字符时，系统将完整内容写入当前工作区内、会话隔离的受控文件，仅在会话历史保留可读预览和重新读取该文件的路径。

- **F3：单条工具消息总量控制**  
  单条工具消息中所有结果的合计超过 `200_000` 字符时，系统按结果字符数从大到小依次外置，直至合计不超限，然后将该消息定型写入历史。外置后仍保留的较小结果必须维持原文。

- **F4：自动全量摘要与原文保留**  
  自动摘要时，系统从会话末尾回溯，保留最新原文消息；保留量必须同时满足“约 `10_000` Token”和“至少 5 条消息”两项下限中的较大者。较早历史由正式摘要替换。

- **F5：手动压缩**  
  用户可以手动触发压缩。手动压缩是无条件立即执行的强制操作，不受当前 Token 估算值限制。

- **F6：结构化摘要内容**  
  正式摘要固定按以下九部分组织：
  1. 主要请求和意图
  2. 关键技术概念
  3. 文件和代码段
  4. 错误和修复
  5. 问题解决过程
  6. 所有用户消息
  7. 待办任务
  8. 当前工作
  9. 可能的下一步

  “所有用户消息”必须逐字保留本会话全部非工具结果的用户原文；“当前工作”必须是最详细的部分。涉及代码、命令和工具结果的内容不得被摘要伪造成已验证事实。

- **F7：受控摘要调用与边界消息**  
  摘要请求不得携带工具声明，且明确禁止模型调用工具。模型先生成仅供内部使用的分析草稿，再生成正式摘要；分析草稿必须丢弃，不能写入会话历史、正式摘要或磁盘。摘要成功后，系统补充边界消息，要求模型需要文件细节时重新读取文件，不得依据摘要臆测代码。

- **F8：摘要失败熔断**  
  摘要连续失败三次后，系统熔断当前会话的后续摘要请求，避免重试循环；任何失败不得破坏压缩前的会话历史。

## 非功能需求

- **N1：近似 Token 估算**  
  不使用精确 tokenizer。系统优先以最近一次可用的 API 输入 Token Usage 为锚点，只对锚点后的变更按字符数估算；Usage 不可用时退化为保守的全文字符估算，不能因此跳过压缩保护。

- **N2：可追溯与隔离**  
  外置文件位于当前工作区且按会话隔离；预览不包含完整大结果，路径可由现有读取工具访问。

- **N3：原子性**  
  外置、摘要生成和历史替换必须原子提交。任一步失败时保留原始历史，不留下半压缩状态。

- **N4：防递归与熔断范围**  
  摘要是独立内部请求，不进入正常 Agent 工具循环，也不再次触发轻量或重量压缩。失败计数仅在当前会话有效；一次成功摘要会清零连续失败计数。

- **N5：兼容性**  
  上下文管理不得改变普通对话、计划执行、权限控制、内置工具或 MCP 工具的既有调用语义。摘要期间取消或 Provider 出错时，当前轮沿用既有错误路径结束。

- **N6：可测试性**  
  所有预算、外置选择、原文保留、熔断和摘要请求约束必须能用无网络测试替身确定性验证；现有完整测试集与静态检查必须保持通过。

## 不做的事

- 不引入精确 tokenizer、模型厂商 Token 计数 API，或 Token 估算精度的自动校准。
- 不自动发现模型上下文窗口；本阶段固定按 `200_000` Token 运行。
- 不实现跨进程会话恢复、长期记忆、摘要检索或不同会话之间的上下文复用。
- 不实现摘要质量评分、机器学习式策略选择、自动调节阈值或自动回滚历史版本。
- 不实现后台压缩、并行摘要或摘要自动重试；压缩只在请求前或用户手动触发时同步执行。
- 不支持图片、音频、嵌入资源等非文本工具结果的解析和摘要。
- 不实现外置文件的自动清理、归档、加密或自定义存储后端；本阶段只保证当前会话中可回读。
- 不改变 Provider 请求协议、模型参数，也不单独为摘要配置模型或 API Key。

## 验收标准

- **AC1：单个结果外置**  
  工具结果恰为 `50_000` 字符时保留原文，超过该值时完整内容落盘，历史只含预览与可读取路径。

- **AC2：工具消息总量控制**  
  五个工具结果为 `42K`、`38K`、`45K`、`40K`、`44K` 字符时，仅 `45K` 结果被外置，其他四项原文保留，定型消息的工具结果合计不超过 `200_000` 字符。

- **AC3：自动摘要阈值与原文尾部**  
  估算完整输入超过 `167_000` Token 时，下一次正常 API 请求前先发生全量摘要；摘要完成后，最新历史仍以原文保留，且保留尾部不少于约 `10_000` Token 或 5 条消息中的较大者。

- **AC4：摘要契约**  
  自动摘要请求不携带工具声明，正式摘要恰含九个约定部分；其中所有用户消息逐字保留，当前工作部分提供最近工作最完整的说明。

- **AC5：回读边界**  
  摘要成功后，后续模型请求能看到结构化摘要和“需要细节请重新读取文件”的边界消息；外置文件可以由既有工具重新读取。

- **AC6：手动压缩**  
  在远低于 `167_000` Token 的会话中手动触发压缩，仍立即执行一次摘要，不会因预算不足而跳过。

- **AC7：熔断与原子性**  
  连续三次摘要失败后，不发起第四次摘要请求，原始历史保持完整，并向用户报告会话已熔断。摘要草稿不进入会话历史或磁盘；摘要、写盘或替换失败时不会留下半压缩历史。

- **AC8：回归验证**  
  普通对话、计划执行、权限和内置/MCP 工具的现有测试保持通过；新增行为可完全通过无网络测试替身验证。
