# OkCode 记忆文件格式与体积感知 Spec

## 背景

当前 `/memory` 只显示项目级和用户级记忆文件名。记忆存储层使用 `index.md` 作为索引，独立记忆文件名来自受限的 `note_ref`；虽然独立文件已经包含 YAML frontmatter，但索引仍带有总标题和分类字段，用户也无法感知记忆文件占用的空间。

## 目标

- 让用户通过 `/memory` 感知项目记忆、用户记忆和两者总占用的文件大小。
- 让每条记忆的 `name` 成为对应独立 Markdown 文件的文件名，并安全支持中文和空格。
- 将项目级和用户级索引统一为 `MEMORY.md`，每行只保存记忆文件指针和内容摘要。
- 兼容已有 `index.md` 索引和旧 frontmatter，避免升级造成已有记忆不可读或不可追加。

## 功能需求

- **F1：`/memory` 体积感知**  
  保留现有项目/用户记忆文件名列表；新增项目记忆大小、用户记忆大小、总大小三行。大小统计各自目录下的全部 `.md` 文件（包含 `MEMORY.md`，不递归子目录），按字节求和，显示两位小数的 `KiB`（1 KiB = 1024 字节）；目录不存在时按 0 KiB。

- **F2：`name` 作为文件名**  
  记忆模型协议使用 `name` 标识记忆；创建或追加时文件路径为 `<name>.md`。允许中文、空格和常见标点，但拒绝路径分隔符、Windows 禁止字符、控制字符、结尾空格/句点、保留设备名和空名称，避免路径穿越与文件覆盖。

- **F3：YAML frontmatter**  
  每个独立记忆文件都写入 `name`、`scope`、`category`、`summary`、`created_at`、`updated_at`；正文只存记忆内容。追加更新只改变 `updated_at`，保留原有元信息。

- **F4：`MEMORY.md` 简洁索引**  
  项目级和用户级目录各使用 `MEMORY.md`；每条记忆一行，格式为 `[name.md](name.md) | 摘要`，不写总标题、不重复整篇正文、不额外维护 meta 文件。

- **F5：旧数据兼容**  
  读取时优先 `MEMORY.md`，不存在时回退读取旧 `index.md`；旧记忆 frontmatter 中的 `id/title` 可继续读取和追加，后续写入转换为新的 `name/summary` 元信息。新写入只生成 `MEMORY.md`，不删除旧的 `index.md`。

## 非功能需求

- **N1：持久化安全**  
  索引和独立记忆继续使用 UTF-8；`MEMORY.md` 与记忆文件采用原子替换写入，校验失败时不产生半写文件。

- **N2：索引约束**  
  沿用每个索引最多 200 行、25 KB 的限制；新格式每行就是一条指针，不额外计入标题行。

- **N3：旧数据兼容**  
  `MEMORY.md` 优先，缺失时读取 `index.md`；旧 `id/title` frontmatter 可读取和追加，不删除用户已有文件。

- **N4：体积统计稳定**  
  统计只读取当前目录下的 `.md` 普通文件；文件不存在或目录不存在按 0 处理，不因单个文件短暂消失阻塞 `/memory`。

- **N5：行为兼容**  
  保留 `/memory` 现有文件名展示和长期记忆上下文注入；后台记忆提炼、普通对话、工具调用、权限、MCP、上下文压缩行为不改变。

- **N6：可测试性**  
  新增逻辑通过无网络单元测试和命令渲染测试验证，不依赖真实 Provider。

## 不做的事

- 不实现向量数据库、Embedding、语义检索或 RAG。
- 不实现团队共享、云端同步、跨设备同步或跨项目复用记忆。
- 不实现记忆文件的可视化管理、手动分类、删除、重命名界面。
- 不递归统计子目录，也不展示每个独立记忆文件的单独大小，只展示项目级、用户级和总大小。
- 不自动删除旧的 `index.md`，只提供读取兼容。
- 不改变记忆后台提炼、Provider 配置、普通会话和上下文压缩流程。
- 不新增数据库、独立 meta 文件或搜索索引。

## 验收标准

- **AC1：`/memory` 展示完整**  
  执行 `/memory` 后，仍能看到项目记忆文件名和用户记忆文件名，并额外看到项目大小、用户大小和总大小，单位为 `KiB`、保留两位小数。

- **AC2：体积计算准确**  
  给项目目录和用户目录放入不同大小的 `.md` 文件后，显示值等于各目录文件字节数之和；包含 `MEMORY.md`，不包含非 `.md` 文件和子目录文件。

- **AC3：`name` 文件名生效**  
  模型返回包含中文或空格的 `name` 时，能创建同名 `.md` 文件；路径分隔符、Windows 禁止字符、控制字符、危险结尾和保留设备名会被拒绝，且拒绝时不写入任何文件。

- **AC4：frontmatter 完整**  
  新建文件包含 `name`、`scope`、`category`、`summary`、`created_at`、`updated_at`；追加后 `name`、分类和创建时间不变，只更新正文、摘要和更新时间。

- **AC5：`MEMORY.md` 格式正确**  
  新索引路径为 `MEMORY.md`，每条记忆恰好占一行，每行包含相对 `.md` 文件指针和摘要，不包含旧的总标题或重复正文。

- **AC6：旧数据可用**  
  只有旧 `index.md` 或旧 `id/title` frontmatter 时，普通上下文读取和追加更新仍成功；新写入生成 `MEMORY.md`，不删除旧文件。

- **AC7：原有约束保留**  
  索引超过 200 行或 25 KB 时拒绝更新，并且此前的记忆文件和索引保持不变。

- **AC8：回归验证通过**  
  新增存储、请求解析、命令事件和终端渲染测试通过，现有全量测试、`uv run ruff check .` 与 `git diff --check` 通过。
