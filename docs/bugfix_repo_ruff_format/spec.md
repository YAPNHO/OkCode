# 全仓 Ruff 格式检查修复 Spec

## 背景

当前使用锁定的 Ruff 0.16.0 执行全仓格式检查时，有 10 个已提交到当前 `HEAD`、且不属于会话权限修复差分的文件被判定为需要重新格式化。它们不会影响 Python 运行，但会导致 `ruff format --check .` 退出码为 1，使全仓格式质量门禁无法通过。

可选方案中，推荐使用项目当前锁定的 Ruff 只格式化这 10 个已识别文件；相比手工调整或改动 Ruff 配置，该方案结果确定、差分可审查，也不会改变项目的格式标准。

## 目标

- 让全仓 `ruff format --check .` 成功通过。
- 只产生 Ruff 自动格式化所需的排版差分，不改变运行逻辑、测试语义或配置。
- 保留工作区中尚未提交的会话权限修复及其文档，不覆盖、不暂存、不提交用户现有改动。

## 功能需求

- F1：使用项目当前锁定的格式化工具处理检查报告中的 10 个文件，使它们符合当前仓库格式规则。
- F2：格式修复不得改变代码行为、公开接口、字符串实际内容、测试断言语义或文件职责。
- F3：格式修复不得触碰已经通过定向格式检查的 7 个会话权限修复代码与测试文件，也不得扩大到其余已合规文件。
- F4：格式修复完成并通过验证后，将会话权限修复 Checklist 中的全仓格式检查结果更新为通过，记录实际验证证据。
- F5：保留当前所有未提交工作，不执行暂存、提交、重置或清理操作。

## 非功能需求

- N1：使用 `uv.lock` 当前解析出的 Ruff 版本，保证结果可复现。
- N2：不新增依赖，不修改 Ruff 配置、Python 版本约束或行宽规则。
- N3：格式化后必须通过全仓测试、Ruff 格式检查、Ruff 静态检查和 Git 空白检查。
- N4：最终差分应能明确区分会话权限修复、格式修复和规格文档，不包含临时文件或调试输出。

## 不做的事

- 不借格式化机会重构、重命名、整理导入或修改业务逻辑。
- 不修改 Ruff 规则来隐藏格式失败。
- 不处理与当前 10 个文件无关的代码风格偏好。
- 不暂存、提交或推送任何文件。

## 验收标准

- AC1：运行 `uv run ruff format --check .` 退出码为 0，不再报告需要格式化的文件。
- AC2：格式修复新增的代码差分只出现在检查原先报告的 10 个文件中，并且均为 Ruff 自动生成的排版变化。
- AC3：运行 `uv run ruff check .` 退出码为 0。
- AC4：运行 `uv run pytest -q` 全量测试通过，现有会话权限回归测试继续通过。
- AC5：运行 `git diff --check` 不报告空白错误。
- AC6：会话权限修复 Checklist 更新为全项通过，并记录本轮实际测试和格式检查结果。
- AC7：Git 状态中不存在由本次操作产生的临时文件、配置改动、暂存内容或提交。
