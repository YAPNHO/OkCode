# OkCode 第六阶段：MCP 客户端与外部工具接入 Spec

## 背景

OkCode 已具备本地工具注册、统一执行、权限控制和 Agent Loop。当前可用工具均由进程内实现，用户无法通过标准 MCP 协议接入外部能力。

本阶段让 OkCode 在启动时读取用户级 `%USERPROFILE%\.okcode\config.yaml` 与项目级 `<项目>\.okcode\config.yaml` 中的 MCP Server 声明，合并同名配置后连接各 Server、发现其工具，并将其作为普通 OkCode 工具注册。Agent 调用远端工具时沿用现有工具调用链路，不感知传输方式或工具来源。

## 目标

- 支持 stdio 子进程和 Streamable HTTP 两种 MCP Server 传输。
- 按 MCP 标准完成初始化、工具发现与工具调用。
- 将远端工具包装为现有统一工具接口，参与模型声明、权限判断与执行结果回灌。
- 缓存多个 Server 的独立连接；单个 Server 启动、发现或调用失败时，不阻塞其他 Server 或内置工具。
- 对 `mcp_servers` 按“项目级覆盖用户级同名 Server”合并，并支持配置值中的 `${VAR}` 环境变量展开。

## 功能需求

- **F1：分层 MCP Server 配置**  
  系统从用户级 `%USERPROFILE%\.okcode\config.yaml` 和项目级 `<项目>\.okcode\config.yaml` 读取 `mcp_servers` 映射。项目级同名 Server 整项覆盖用户级配置，未重名的 Server 合并保留。`stdio` Server 声明 `command`、可选 `args` 与 `env`；`streamable_http` Server 声明 `url` 与可选 `headers`。所有配置字符串支持 `${变量名}` 展开；引用不存在的环境变量或字段组合不合法时，给出定位到 Server 名称和字段的配置错误。

- **F2：启动时发现工具**  
  OkCode 启动后，对每个已合并的 MCP Server 独立建立会话，依次完成初始化握手和工具列表查询。成功发现的工具注册到当前工具中心；内置工具始终保留。

- **F3：标准 MCP 工具会话**  
  每个连接通过 JSON-RPC 2.0 发送请求并按请求标识关联异步响应。一次工具会话至少支持初始化、列出工具和调用工具三类请求；协议错误、服务端返回错误或无效响应均转换为该 Server 可诊断的失败，不影响其他连接。

- **F4：远端工具适配**  
  每个发现到的远端工具保留其描述和输入 JSON Schema，并包装为 OkCode 的统一工具能力。Agent 请求该工具时，适配层将参数转发给对应 MCP Server，并把文本结果、结构化结果或错误结果转换为现有统一工具执行结果。

- **F5：工具命名与冲突规避**  
  注册时将远端工具命名为 `mcp__<server_name>__<tool_name>`，以避免不同 Server 间及与内置工具的名称冲突。模型看到并调用的是该唯一名称；适配层自动还原原始远端工具名，Server 不感知 OkCode 的命名规则。

- **F6：连接缓存与故障隔离**  
  同一 Server 在一次 OkCode 进程生命周期内复用一个已初始化连接，不在每次工具调用时重复握手。单个 Server 连接、发现或调用失败时，仅跳过或失败该 Server 的工具；其他 MCP Server、内置工具和 REPL 继续可用。

- **F7：生命周期收尾**  
  OkCode 退出时，按已建立连接逐个关闭远程会话、HTTP 客户端或子进程管道，并保证关闭一个连接失败不会阻止其余资源清理。

## 非功能需求

- **N1：启动隔离与有界等待**  
  MCP Server 的连接与工具发现相互独立，并行进行；单个 Server 无响应、握手失败或工具列表失败，不得阻塞其他 Server 的发现或 OkCode REPL 启动。配置错误属于启动错误；连接错误属于可恢复的 Server 级错误。

- **N2：配置校验与密钥保护**  
  严格校验 `mcp_servers` 的名称、传输类型、必填字段和字段类型。错误信息应指出配置来源、Server 名称与字段，但不得输出环境变量展开后的敏感值、HTTP 认证头或环境变量内容。

- **N3：现有执行链路兼容**  
  远端工具必须经过现有注册、参数 Schema 校验、超时、权限判断、结果截断和会话历史回灌链路。未能可靠识别为只读的远端工具默认按有副作用处理，沿用当前权限策略。

- **N4：资源可靠释放**  
  正常退出、启动中断和异常退出路径均释放已创建的子进程、标准输入输出管道与 HTTP 会话，不遗留后台进程或未关闭连接。

- **N5：可测试性**  
  测试使用可控的本地 stdio 和 Streamable HTTP MCP Server，覆盖握手、分页工具发现、成功调用、服务端错误、协议错误、超时、配置覆盖、环境变量展开、命名冲突和多 Server 隔离。

## 不做的事

- 不实现 MCP 资源、提示词、采样、根目录协商等非工具能力。
- 不实现健康检查、重试、自动重连或后台保活；已断开的 Server 本次进程内保持不可用状态。
- 不实现 OAuth 等专用认证流程；HTTP 认证通过用户配置的 `headers` 提供。
- 不把图片、音频或嵌入资源等非文本 Tool Result 转换为模型可消费内容；首版支持文本内容和结构化 JSON 结果。
- 不改变内置工具名称、行为和现有权限规则优先级。

## 配置与验收标准

- **AC1：配置合并**  
  用户级与项目级各声明 `mcp_servers` 后，启动时同时得到未冲突的 Server；同名 Server 以项目级完整配置为准。

- **AC2：环境变量展开**  
  stdio 的 `args`、`env` 和 HTTP 的 `url`、`headers` 中的 `${VAR}` 被正确替换；未定义变量使启动以明确配置错误结束，且错误中不泄漏敏感值。

- **AC3：stdio 工具发现与调用**  
  配置一个可控的 stdio Server 后，OkCode 完成初始化和 `tools/list`，模型可调用发现的 `mcp__<server>__<tool>`，并得到与 Server 返回内容一致的工具结果。

- **AC4：Streamable HTTP 工具发现与调用**  
  配置一个可控的 Streamable HTTP Server 及自定义请求头后，OkCode 完成同样的初始化、发现和调用流程，并正确附带配置头。

- **AC5：多 Server 隔离**  
  两个可用 Server 与一个不可用 Server 同时配置时，两个可用 Server 的工具仍会注册和调用；不可用 Server 仅产生可诊断警告，不导致 REPL 或内置工具失效。

- **AC6：名称唯一性**  
  两个 Server 暴露同名工具，或远端工具名与内置工具名相同，均可通过 `mcp__<server>__<tool>` 唯一注册和正确路由。

- **AC7：退出清理**  
  启动后退出 OkCode，stdio 子进程和 HTTP 连接被关闭；某一连接关闭异常时，其余连接仍继续清理。

- **AC8：回归验证**  
  现有本地工具、权限系统、普通对话与 Agent Loop 的完整测试集保持通过。
