# OkCode 第八阶段：会话恢复与长期记忆 Spec

## 背景

OkCode 当前仅在进程内保存 `ConversationSession` 的消息。进程结束后，用户必须从零开始提供项目背景、个人偏好和此前任务的关键信息；中断的工作也没有可供主动恢复的会话存档。

第八阶段引入短期会话与长期记忆的分层管理。每次正常启动都创建新的短期会话，不自动回载旧对话；在第一轮模型请求前，系统加载项目指令和长期记忆索引，使 Agent 在新会话中仍具备项目背景与用户偏好。已完成会话持续写入项目内的 JSONL 存档，用户可通过 `/resume` 显式选择一个会话恢复其短期历史。

## 目标

- 让新的 OkCode 会话自动具备当前项目的指令、项目知识和用户偏好，而不携带旧会话的普通消息。
- 让用户通过 `/resume` 查看当前项目可恢复会话并选择其中一项继续工作。
- 用可容错的 JSONL 存档保存会话，以支持中断后的可靠恢复。
- 在每轮 Agent 自然结束后异步提炼可复用的长期记忆，并在后续请求前以受限索引注入上下文。

## 功能需求

- **F1：分层项目指令加载**  
  系统加载项目根、项目根 `.okcode/` 目录和用户 `.okcode/` 目录中的手写 Markdown 指令。项目根指令优先级最高，项目 `.okcode/` 指令次之，用户指令最低；渲染到模型上下文时高优先级内容必须排在前面。指令支持 `@include` 引用其他文件，系统必须限制引用嵌套深度、检测已访问文件以阻止循环，且拒绝解析后跳出项目根目录的引用目标。

- **F2：新会话与 JSONL 存档**  
  每次正常启动创建新的短期会话，并为其生成 `YYYYMMDD-HHMMSS-xxxx` 格式的唯一 ID。会话消息追加写入当前项目 `sessions/` 目录中对应的 JSONL 文件；会话 ID、标题、消息数和最近更新时间等展示信息必须直接由 JSONL 计算，不得维护独立 meta 文件。

- **F3：显式恢复会话**  
  用户输入 `/resume` 后，系统展示当前项目未过期会话的列表，包含 ID、标题、消息数和最近更新时间；用户选择一项后才恢复其短期对话历史。恢复时必须跳过损坏行；发现工具调用没有匹配工具结果时，截断该调用及其后的不完整历史；恢复后的请求超过上下文预算时，先执行一次已有的上下文压缩；会话中断时间较长时，在下一次模型请求前加入明确的时间跨度提醒。

- **F4：过期会话清理**  
  系统定期清理当前项目 `sessions/` 目录中超过 30 天的会话存档；过期会话不出现在 `/resume` 的可选列表中。

- **F5：自然结束后的自动笔记**  
  每轮 Agent Loop 成功自然结束、且模型最终回复不包含工具调用时，系统在后台异步请求 LLM，从本轮内容中提炼用户偏好、纠正反馈、项目知识和参考资料四类长期笔记。LLM 负责判断笔记是否值得新增、更新既有笔记或因重复而不作变更。

- **F6：分级笔记与上下文注入**  
  用户级笔记和项目级笔记必须分开保存；每条笔记是带 frontmatter 的 Markdown 文件。系统在处理每个普通模型请求前读取长期记忆索引并注入上下文，使 Agent 在新会话中已具备相关背景。索引内容不得超过 200 行或 25KB。

- **F7：后台失败隔离**  
  自动笔记提炼或索引更新失败不得影响已完成的用户回答、会话存档或后续普通对话；成功写入的记忆仅保证在后续请求中生效。

## 非功能需求

- **N1：JSONL 崩溃容错**  
  会话存档采用每行独立 JSON 的追加写入。异常退出后的恢复必须保留所有可解析的完整行，至多舍弃不完整的末行。

- **N2：恢复历史有效性**  
  恢复后的消息序列必须符合 Provider 的工具调用配对约束，不得将不完整的工具历史发送给模型。

- **N3：引用路径安全性**  
  所有 `@include` 路径在规范化后必须位于项目根目录内；循环引用和超过嵌套深度限制时，系统必须给出可定位的错误信息。

- **N4：异步隔离**  
  自动笔记提炼在后台运行，不得阻塞终端显示、下一轮输入或正常 Agent Loop。

- **N5：持久化格式与索引上限**  
  指令、会话和记忆文件均使用 UTF-8 文本。记忆索引的截断或更新必须保持可解析，且不得超过 200 行和 25KB。

- **N6：可测试性与兼容性**  
  新行为必须可通过无网络的单元测试替身确定性验证；现有普通对话、工具调用、权限、MCP 与上下文压缩行为不得回归。

## 不做的事

- 不引入向量数据库、嵌入模型、语义检索或 RAG。
- 不实现团队共享记忆、云端同步、跨设备同步或跨项目的记忆复用。
- 不在启动时自动恢复任意旧会话，也不实现会话分支、合并或导出。
- 不维护会话 meta 文件、数据库或独立搜索索引。
- 不实现笔记的人工分类工作流、可视化管理界面或跨会话自动回溯全文。
- 不新增独立的记忆模型、API Key 或 Provider 配置；自动笔记使用当前会话已配置的 LLM。

## 验收标准

- **AC1：分层指令和安全引用**  
  三层指令按项目根、项目 `.okcode/`、用户目录的优先级注入；嵌套引用能够展开，循环引用、嵌套过深和越出项目根目录的路径均被拒绝。

- **AC2：新会话 JSONL 存档**  
  启动后生成格式正确且不重复的会话 ID，消息追加到对应 JSONL；扫描该文件可获得 ID、标题、消息数和最近更新时间，且不存在独立 meta 文件。

- **AC3：显式恢复而非自动恢复**  
  `/resume` 展示未过期会话，用户选中后才恢复；普通启动仍创建新会话，旧会话的普通消息不进入新会话的第一轮模型请求。

- **AC4：损坏与不完整历史恢复**  
  恢复包含坏行的 JSONL 时跳过坏行；末尾工具调用缺少工具结果时，恢复历史截断到最后一个合法消息边界。

- **AC5：恢复后的上下文与时间边界**  
  恢复后的历史超出预算时，系统先执行一次上下文压缩；两次工作时间相隔较久时，下一次模型请求中可观察到时间跨度提醒。

- **AC6：过期清理**  
  超过 30 天的会话存档被清理，且不会出现在 `/resume` 会话列表中。

- **AC7：自动笔记更新**  
  一轮最终回答成功提交后，后台任务能够写入或更新四类笔记；LLM 判断无需变更时不产生重复笔记。

- **AC8：分级记忆注入与索引限制**  
  新会话的模型请求包含项目级和用户级记忆索引；两类笔记存放在不同目录，索引始终不超过 200 行和 25KB。

- **AC9：异步故障隔离与回归**  
  自动笔记任务失败或延迟时，当前回答已经返回，下一轮仍可正常开始；全部现有测试和新增离线测试通过。
