# OkCode 第十三阶段：子 Agent Worktree 隔离 Spec

## 背景

第十二阶段已经让 OkCode 支持主 Agent 委派定义式子 Agent、Fork 式子 Agent、后台任务、Hook 触发和任务通知。该阶段刻意没有实现 Worktree 文件隔离，因此当前子 Agent 虽然拥有独立消息、权限、缓存和任务状态，但文件工具仍然作用于同一个仓库工作目录。

当主 Agent 与一个或多个子 Agent 并行修改同一仓库时，共用工作目录会带来明显风险：一方尚未完成的修改可能被另一方读取、覆盖、格式化或误判；后台子 Agent 的长期任务也可能影响主 Agent 当前上下文中的文件状态。为了让主 Agent 能放心把可修改任务派给子 Agent，需要为需要隔离的子 Agent 提供独立 Git worktree。

本阶段为 OkCode 增加子 Agent Worktree 隔离能力：当角色声明需要 worktree 隔离，或启动请求明确要求 worktree 隔离时，OkCode 在同一 Git 仓库内创建受管理的独立工作目录、独立分支和独立运行环境。子 Agent 的所有文件工具、命令工具、项目指令、系统提示词、记忆读取和路径相关缓存都以该 worktree 的绝对路径为边界；主 Agent 继续留在原工作目录。子 Agent 完成后，OkCode 根据变更状态决定清理或保留 worktree，并提供后台过期清理机制。

## 目标

- 用 Git 自带的 worktree 机制为需要隔离的子 Agent 创建独立工作目录和独立分支。
- 把 worktree 目录放在仓库内已忽略的 OkCode 本地状态区域，避免被普通版本控制追踪。
- 对 worktree 名称和相对路径做严格安全校验，防止模型输入造成路径遍历或覆盖非管理目录。
- 提供完整生命周期：创建、快速恢复、进入、退出、删除和过期清理。
- 创建后初始化子 Agent 运行环境，让被隔离 worktree 能直接复用必要本地配置、Git hooks、大型依赖目录和被忽略但运行所需文件。
- 保持工具调用显式工作目录模型：不通过进程级切换目录实现隔离，而是把目标 worktree 作为显式 cwd 传入所有文件、命令、指令、记忆和缓存相关路径。
- 通过角色 frontmatter 字段 isolation: worktree 声明隔离需求，并在子 Agent 启动时自动应用。
- 在删除和自动清理前保护未提交修改、未推送提交和无法确认状态的 worktree。

## 功能需求

- **F1：隔离声明**
  OkCode 必须支持子 Agent 角色声明是否需要 worktree 隔离。角色未声明时保持现有共享工作目录行为；角色声明 worktree 隔离时，子 Agent 启动前必须进入受管理的独立 worktree。启动请求也可以显式要求 worktree 隔离，但不得绕过角色或全局安全限制。

- **F2：Git worktree 创建**
  当需要隔离时，OkCode 必须在当前 Git 仓库内创建一个新的 Git worktree，并为该 worktree 绑定独立分支。创建成功后，子 Agent 看到的仓库文件来自该独立工作目录；主 Agent 的工作目录不变。

- **F3：受管理目录位置**
  所有自动创建的 worktree 必须位于仓库内的 OkCode 本地状态区域下，该区域必须默认不被 Git 追踪。OkCode 不得在用户任意传入的绝对路径或仓库外路径创建、进入或删除 worktree。

- **F4：安全名称校验**
  Worktree 名称必须通过严格校验后才能参与路径拼接。名称只能由大小写英文字母、数字、短横线、下划线、点号和正斜杠组成；允许用正斜杠表示有限层级嵌套；每一段都不能为空，且不能是单点或双点；整体长度和单段长度都必须有上限。非法名称必须被拒绝并给出可定位错误，不得尝试修正后继续执行。

- **F5：快速恢复**
  如果目标 worktree 目录已经存在，OkCode 必须优先走只读恢复检查：验证该目录位于受管理区域内、包含 OkCode 管理元数据、指向同一 Git 仓库并且和预期任务身份匹配。恢复检查通过时直接复用该目录，不再调用 git 创建命令；恢复检查失败时必须拒绝进入，不能覆盖目录。

- **F6：进入隔离工作区**
  子 Agent 进入隔离模式后，所有文件读取、文件写入、搜索、命令执行、项目指令加载、记忆读取、会话产物和路径相关缓存都必须使用 worktree 的绝对路径作为工作区根。OkCode 不得依赖进程级 chdir 切换当前目录来实现隔离。

- **F7：路径缓存隔离**
  文件内容缓存、系统提示词缓存、项目指令缓存、记忆缓存和其他路径相关缓存必须以绝对路径作为 key，或等价包含绝对工作区根。主工作区与任意 worktree 即使相对路径相同，也不得共享会导致读取错误的缓存项。

- **F8：环境初始化**
  Worktree 创建后必须执行环境初始化。初始化至少覆盖本地配置复制、子目录 Git hooks 配置、大型依赖目录复用，以及按规则补齐被 Git 忽略但运行需要的文件。初始化必须是幂等的；重复进入同一个已恢复 worktree 不得破坏已有本地修改。

- **F9：本地配置复制**
  OkCode 必须把子 Agent 运行必需且允许复制的本地配置复制到 worktree。复制范围只包含项目本地配置、权限配置、MCP 配置、角色或指令所需的本地文件等运行必需项；不得默认复制会扩大权限、泄露无关凭据或与本任务无关的大型目录。

- **F10：Git hooks 配置**
  Worktree 必须能使用与主工作区一致或等价的 Git hooks。OkCode 需要在 worktree 内配置 hooks 路径或复制必要 hooks 文件，使子 Agent 在该 worktree 中执行 Git 相关命令时能触发预期 hooks。

- **F11：大型依赖目录复用**
  对虚拟环境、依赖缓存、包管理缓存等大型目录，OkCode 应按平台能力优先创建安全软链或目录连接来复用主工作区资源。无法创建链接时必须给出明确降级行为，例如跳过并提示需要用户手动初始化，不能静默生成不完整环境。

- **F12：被忽略运行文件补齐**
  对被 Git 忽略但运行测试或工具所需的文件，OkCode 必须支持受控规则来补齐到 worktree。补齐规则必须可审计、可测试，默认只覆盖 OkCode 已知运行必需文件，不得把所有被忽略内容无差别复制到 worktree。

- **F13：路径说明注入**
  子 Agent 启动时，OkCode 必须在其运行环境说明中注入当前隔离 worktree 的绝对路径、主工作区绝对路径、当前分支、清理策略和禁止跨目录直接改动的约束。该说明只进入子 Agent 上下文，不污染主 Agent 的普通系统提示词。

- **F14：退出隔离工作区**
  子 Agent 完成、失败、取消或超时时，OkCode 必须执行退出流程：刷新 worktree 状态、生成变更摘要、判断是否可清理、记录最终路径和分支信息，并把必要信息返回主 Agent 或后台任务结果。

- **F15：删除保护**
  删除 worktree 前必须检查未提交修改、未跟踪文件、暂存区变更、未推送提交和无法确认 upstream 的分支。存在任一风险时默认拒绝删除，并返回保留路径、分支名和需要用户处理的原因。

- **F16：自动清理策略**
  子 Agent 完成后，如果 worktree 没有文件变更、没有未推送提交、没有未跟踪文件，并且状态可完全确认，OkCode 可以自动删除该临时 worktree。只要存在不确定状态，就必须保留并报告，不能强制清理。

- **F17：显式删除**
  OkCode 必须提供显式删除受管理 worktree 的能力。显式删除也必须经过删除保护；用户明确要求强制删除时，系统仍必须验证目标属于受管理目录、属于同一仓库且匹配管理元数据。

- **F18：后台过期清理**
  OkCode 必须提供后台过期清理机制，定期扫描受管理 worktree。清理必须经过三层过滤：路径位于受管理区域、目录含 OkCode 管理元数据、Git worktree 状态与元数据匹配。只有同时通过过滤且无变更风险的过期目录才能清理。

- **F19：状态可观测**
  Worktree 的创建、恢复、初始化、进入、退出、保留、删除、清理跳过和清理失败都必须可观测。主 Agent 能看到子 Agent 最终使用的 worktree 路径、分支、变更摘要和清理结果；后台任务查询也能展示隔离状态。

- **F20：错误隔离**
  Worktree 创建、恢复、初始化或删除失败不得导致主 Agent 会话崩溃。失败必须作为子 Agent 启动失败、任务失败或清理失败结果返回，并包含可行动原因。其他正在运行的子 Agent 和主 Agent 工作目录不得受影响。

## 非功能需求

- **N1：主流程兼容**
  未启用 worktree 隔离时，现有主 Agent、子 Agent、工具、权限、Hook、Skill、记忆、上下文管理、会话存档和命令行为必须保持不变。

- **N2：安全优先**
  所有 worktree 路径必须由 OkCode 管理目录和安全名称派生，不信任模型给出的绝对路径。任何删除动作都必须先证明目标是 OkCode 管理的 worktree。

- **N3：Windows 友好**
  实现必须兼容 Windows 环境。软链或目录连接能力不足时，系统必须有明确降级路径和用户可理解的提示。

- **N4：可恢复**
  进程中断、子 Agent 失败或清理失败后，已创建的 worktree 必须能被后续启动识别、恢复、保留或安全清理，不能只能依赖内存状态。

- **N5：可测试**
  主要行为必须能用临时 Git 仓库、假子 Agent、假初始化规则和本地文件系统确定性测试，不依赖真实远程仓库、真实模型服务或危险命令。

- **N6：最小副作用**
  Worktree 隔离只能影响声明需要隔离的子 Agent。主 Agent 当前工作区、其他 worktree、全局 Git 配置和用户仓库外文件不得被修改。

- **N7：性能可控**
  创建和恢复路径应尽量复用 Git worktree、链接大型依赖和幂等初始化，避免每次子 Agent 启动都复制完整仓库或完整依赖目录。

## 不做的事

本阶段明确不包含：

- 不实现 worktree 之间的合并策略；合并、冲突处理和最终取舍交给上层通过 Git merge、rebase 或人工流程决定。
- 不实现跨 worktree 的实时代码同步、文件广播或自动同步补丁。
- 不实现多 Agent 并行编排、任务图调度或 Agent 间协作协议。
- 不让子 Agent 绕过现有工具权限、Hook 拦截、后台白名单或工作区路径约束。
- 不把所有子 Agent 默认切换到 worktree；只有角色或启动请求声明需要时才启用。
- 不支持任意仓库外目录作为 worktree 管理目录。
- 不默认复制所有被 Git 忽略文件、用户密钥、缓存和大型依赖目录。
- 不要求所有 Provider 或所有外部工具知道 worktree 概念；隔离由 OkCode 的工作区和工具执行边界保证。

## 验收标准

- **AC1（覆盖 F1、N1）**：未声明 worktree 隔离的子 Agent 按现有共享工作目录路径运行；声明 isolation: worktree 的角色启动时自动创建或恢复隔离 worktree。

- **AC2（覆盖 F2、F3）**：在临时 Git 仓库中启动隔离子 Agent 后，能观察到受管理目录下出现 Git worktree，且该 worktree 绑定独立分支；主工作目录路径保持不变。

- **AC3（覆盖 F4、N2）**：合法名称可创建嵌套 worktree；包含绝对路径、父级回退、空段、单点段、双点段、非法字符或超长内容的名称全部被拒绝，且不会创建目录。

- **AC4（覆盖 F5、N4）**：当目标受管理目录已存在且元数据匹配时，启动流程复用目录且不调用 git 创建命令；当目录存在但元数据缺失或不匹配时，启动流程拒绝覆盖。

- **AC5（覆盖 F6、F7）**：隔离子 Agent 的文件读取、写入、搜索、命令执行、项目指令、记忆和路径缓存全部以 worktree 绝对路径为根；相同相对路径在主工作区和 worktree 中能读到各自内容。

- **AC6（覆盖 F8、F9、F10、F11、F12、N3、N7）**：新建 worktree 后，本地配置、Git hooks、大型依赖复用和被忽略运行文件补齐按规则完成；重复初始化保持幂等；Windows 链接失败时给出明确降级提示。

- **AC7（覆盖 F13、F19）**：子 Agent 上下文能看到隔离 worktree 路径、主工作区路径、分支和清理约束；主 Agent 最终能看到子 Agent 使用的路径、分支、变更摘要和清理结果。

- **AC8（覆盖 F14、F15、F16、F17）**：无变更、无未推送提交且状态确认的临时 worktree 会被清理；存在未提交修改、未跟踪文件、暂存区变更、未推送提交或无 upstream 的分支时默认保留并报告原因；显式删除同样遵守保护。

- **AC9（覆盖 F18、N2、N4）**：后台过期清理只删除同时满足受管理路径、元数据匹配、Git worktree 状态匹配且无变更风险的目录；不满足任一条件时跳过并记录原因。

- **AC10（覆盖 F20、N5、N6）**：创建、恢复、初始化或删除失败会返回结构化错误，不导致主 Agent 崩溃；测试使用临时仓库和假子 Agent 覆盖成功、拒绝、保留和清理失败路径。
