# OkCode 第十一阶段：Hooks 自动化机制 Spec

## 背景

OkCode 已具备多轮 Agent Loop、本地工具执行、五层权限系统、上下文管理、命令系统和 Skill 机制。当前一些生命周期固定、触发条件明确、动作重复的工作仍需要人工盯着执行，例如在工具执行前做额外拦截、在轮次开始注入固定上下文、在工具执行后触发格式化命令或通知外部服务。

本阶段为 OkCode 增加声明式 Hooks 机制。用户通过 YAML 定义“事件 + 条件 + 动作”规则，OkCode 在 Agent 生命周期的关键节点自动匹配并执行动作。Hook 失败只记录日志，不应破坏 Agent 主流程；但工具执行前的拦截类 Hook 可以阻止该工具执行，并把拒绝原因作为工具结果反馈给模型，让模型调整参数、换工具或解释风险。

## 目标

- 让格式化、拦截、上下文注入、通知等固定重复动作从人工操作变成生命周期自动触发。
- 用统一规则格式表达 Hook：事件必须有，动作必须有，条件可省略。
- 覆盖会话级、轮次级、消息级、工具级以及少量系统级生命周期事件。
- 在工具执行前提供可拦截的安全策略入口，支持基于工具参数的细粒度判断。
- 复用权限规则的匹配语法与安全加载习惯，降低用户学习成本。
- 支持 shell 命令、提示词注入、HTTP 请求、子 Agent 四类动作；其中子 Agent 本阶段只占位校验，不真实运行。
- 提供 /hooks 命令查看当前已加载 Hook 列表和关键状态。

## 功能需求

- **F1：声明式 Hook 规则**
  OkCode 必须从 YAML 加载 Hook 规则。每条规则由 event、可选 if、action 三部分组成：event 表示触发时刻，if 表示触发条件，action 表示要执行的动作。缺少 event 或 action 的规则必须在加载阶段报错；缺少 if 表示无条件触发。

- **F2：生命周期事件覆盖**
  Hook 事件必须覆盖五类生命周期：会话级、轮次级、消息级、工具级和系统级。会话级至少包含会话开始、会话结束；轮次级至少包含轮次开始、轮次结束；消息级至少包含用户消息接收后、模型消息完成后；工具级至少包含工具执行前、工具执行后；系统级至少包含上下文压缩后和错误记录后。事件名称必须稳定、可在 /hooks 中展示，并在未知事件出现时于加载阶段报错。

- **F3：工具执行前拦截**
  工具执行前事件必须允许 Hook 拦截工具调用。拦截判断必须发生在真实工具产生副作用之前；拦截后工具不得执行，OkCode 必须把拒绝原因封装为该工具调用的失败结果并写回对话历史。模型下一步能看到这次失败原因，并可据此调整工具参数、改用其他工具或给用户解释。

- **F4：条件表达式**
  if 条件必须能够匹配事件上下文中的字段，例如工具名、工具参数、消息内容、运行模式、工作区相对路径、错误类别等。条件匹配语法复用权限规则语义，支持精确匹配、反向匹配、正则匹配和 glob 匹配。无效字段、无效匹配类型、无效正则或类型不匹配必须在加载阶段给出可定位错误。

- **F5：条件逻辑组合**
  一条 Hook 规则内的多个条件只能选择“全部满足”或“任一满足”一种组合方式。默认组合方式为全部满足。单条规则内不得同时混用全部满足和任一满足；混用时必须在加载阶段报错。没有条件的规则不参与逻辑组合，直接视为命中。

- **F6：Shell 命令动作**
  Hook 必须支持执行 shell 命令动作。命令动作必须能声明命令文本、可选工作目录、可选超时时间、是否只运行一次、是否后台异步执行。命令执行的标准输出、标准错误、退出码和超时状态必须进入 Hook 日志；非拦截事件中的命令失败不得中断 Agent 主流程。

- **F7：提示词注入动作**
  Hook 必须支持提示词注入动作。注入内容必须进入后续模型请求可见的上下文，而不是伪造用户消息或破坏已有工具调用与工具结果配对。注入必须有明确作用范围：当前轮次、当前会话，或针对某个触发事件后的下一次模型请求。注入结果应能在测试中观察到。

- **F8：HTTP 请求动作**
  Hook 必须支持发起 HTTP 请求动作。请求动作至少能声明 URL、方法、请求头、请求体、超时时间，以及是否后台异步执行。请求成功、失败、状态码、超时与异常必须进入 Hook 日志；HTTP 动作失败不得中断 Agent 主流程。

- **F9：子 Agent 动作占位**
  Hook YAML 必须接受子 Agent 动作的声明，并完成字段校验与 /hooks 展示；但本阶段不得真实启动子 Agent。运行时命中子 Agent 动作时，OkCode 只记录“已跳过，等待 SubAgent 阶段对接”的日志，不产生子 Agent 副作用。

- **F10：执行控制**
  Hook 动作必须支持三类执行控制：只跑一次、后台异步、命令或请求超时。只跑一次只要求在当前进程内生效，本阶段不做跨进程或跨重启持久化。后台异步动作不得阻塞 Agent 主流程；超时必须终止或放弃对应动作并记录日志。拦截类事件不允许异步执行；配置为异步时必须加载失败。

- **F11：Hook 失败隔离**
  除工具执行前的明确拦截结果外，Hook 自身加载后的运行失败、命令失败、HTTP 失败、模板渲染失败、超时或内部异常，都只能记录日志，不得中断会话、轮次、消息处理、工具执行或上下文压缩主流程。

- **F12：集中加载与校验**
  Hook 规则必须从 YAML 声明式加载，并在启动或刷新时集中校验。校验至少覆盖必填字段、未知字段、事件名、动作类型、条件字段、匹配表达式、执行控制限制和拦截事件限制。存在无效规则时，OkCode 必须报告具体文件、规则索引和字段位置。

- **F13：/hooks 命令**
  OkCode 必须提供 /hooks 命令查看已加载 Hook 列表。输出至少包含规则名称或序号、事件、条件摘要、动作类型、是否启用、是否只跑一次、是否异步、超时设置，以及子 Agent 占位状态。没有加载任何 Hook 时，命令必须给出明确空状态。

## 非功能需求

- **N1：主流程稳定性**
  Hook 机制不得改变无 Hook 配置时的既有行为。普通对话、命令系统、权限系统、工具结果写回、上下文压缩、Skill 激活和会话持久化必须保持原有语义。

- **N2：安全优先**
  工具执行前拦截必须早于真实工具副作用。Hook 条件可以读取必要事件上下文，但不得把敏感绝对路径、内部正则细节或未脱敏异常直接暴露给模型或终端。

- **N3：可观测性**
  Hook 加载、命中、跳过、执行成功、执行失败、超时、拦截和子 Agent 占位跳过都必须可记录到日志或可测试事件中。用户通过 /hooks 至少能看到加载结果和规则摘要。

- **N4：配置可维护性**
  Hook YAML 必须使用安全加载与严格字段校验。缺失 Hook 配置按空规则处理；存在但格式错误的配置必须阻止启动或刷新，并给出定位信息。

- **N5：测试友好**
  条件匹配、事件触发、工具执行前拦截、提示词注入、shell 命令超时、HTTP 请求失败、后台异步隔离、只跑一次、子 Agent 占位和 /hooks 输出，都必须能在不访问真实模型服务、不执行危险命令、不依赖真实外网的测试中验证。

## 不做的事

本阶段明确不包含：

- 不实现子 Agent 动作的真实运行，只做配置校验、展示和命中时跳过日志。
- 不实现只跑一次标记的跨进程、跨会话或跨重启持久化。
- 不实现 Hook 执行顺序的显式优先级；同一事件下的执行顺序只需稳定且可预测。
- 不提供图形化 Hook 管理界面。
- 不提供 Hook 配置热重载的文件监听机制，除非已有命令或启动流程自然触发重新加载。
- 不把 Hook 作为绕过权限系统、工作区沙箱或工具参数校验的入口。
- 不为 HTTP 动作实现重试、鉴权插件、代理配置或复杂签名协议。
- 不为 shell 命令动作实现交互式输入、长驻前台进程管理或终端 UI 接管。

## 验收标准

- **AC1（覆盖 F1、F12、N4）**：给定有效 YAML，OkCode 成功加载 Hook；给定缺少 event、缺少 action、未知字段或未知事件的 YAML，启动或刷新阶段报出包含文件、规则索引和字段的配置错误。

- **AC2（覆盖 F2）**：会话级、轮次级、消息级、工具级和系统级事件各至少有一个可测试触发点；测试能观察到对应 Hook 被命中或跳过。

- **AC3（覆盖 F3、N2）**：工具执行前 Hook 根据工具名和参数命中拦截条件时，真实工具替身执行计数为零；对话历史中写入该工具调用的失败结果，失败内容包含可行动的拒绝原因。

- **AC4（覆盖 F4、F5）**：条件表达式能分别完成精确、反向、正则、glob 匹配；多个条件在“全部满足”模式和“任一满足”模式下结果正确；混用两种组合方式或提供无效正则时加载失败。

- **AC5（覆盖 F6、F10、F11）**：shell 命令动作能正常执行并记录退出码；超时命令被终止或放弃并记录超时；非拦截事件中的命令失败不会中断 Agent 主流程。

- **AC6（覆盖 F7）**：提示词注入 Hook 命中后，下一次符合范围的模型请求包含注入内容；注入不会生成伪造用户消息，也不会拆开 assistant tool_calls 与 tool result 的配对。

- **AC7（覆盖 F8、F10、F11）**：HTTP 动作能构造指定方法、URL、请求头和请求体；请求失败、非 2xx 状态或超时只记录日志，不中断 Agent 主流程。

- **AC8（覆盖 F9）**：子 Agent 动作配置能通过合法字段校验并在 /hooks 中展示；命中时不启动真实子 Agent，只记录占位跳过结果。

- **AC9（覆盖 F10）**：只跑一次的 Hook 在同一进程内首次命中后执行，后续命中跳过并记录原因；后台异步 Hook 不阻塞主流程；工具执行前拦截事件配置异步时加载失败。

- **AC10（覆盖 F13、N3）**：/hooks 在无配置时显示空状态；有配置时展示事件、条件摘要、动作类型、启用状态、只跑一次、异步、超时和子 Agent 占位信息。

- **AC11（覆盖 N1、N5）**：未配置 Hook 时，既有单元测试和集成测试保持通过；新增测试不依赖真实外网、真实模型服务或危险命令。
