# OkCode 第五阶段：五层权限系统 Checklist

> 每项都通过运行测试或观察真实终端行为验证，重点检查调用是否真正被阻止、规则是否按正确层级生效，以及权限失败是否仍能让 Agent Loop 继续。

## 实现完整性

- [ ] 所有已注册本地工具在实际执行前都经过统一权限决策；对被拒绝调用，工具替身执行次数为零。（验证：运行执行器单元测试，检查允许路径执行一次、拒绝路径零次。）
- [ ] `run_command` 的 Windows 高危删除、格式化、磁盘/分区破坏、启动配置破坏、强制关机和重启样本均被黑名单拒绝。（验证：运行 `test_permissions_blacklist.py`，不创建真实子进程。）
- [ ] 黑名单命令即使同时命中 `allow` 规则、`allow` 模式或人工允许，也仍返回来源为 `blacklist` 的拒绝。（验证：使用权限管理器测试三种绕过尝试均未通过。）
- [ ] 文件与目录目标在解析已有符号链接或 Windows 重解析点后仍位于项目目录内才被允许。（验证：工作区测试对项目内路径成功，对外部符号链接或目录联接返回 `outside_workspace`。）
- [ ] 空路径、`..` 回退、绝对路径、UNC 路径、盘符根目录和经已存在父目录链接逃逸的写入目标全部被拒绝。（验证：运行工作区路径测试；不能创建链接的平台只跳过相关链接项。）
- [ ] `工具名` 与 `工具名(模式)` 规则正确解析；`Bash(...)` 与 `run_command(...)` 等价。（验证：规则解析测试覆盖纯工具名、别名、精确命令和路径模式。）
- [ ] 规则精确匹配只命中完整目标，glob 匹配命中预期命令或项目相对路径；Windows 路径分隔符和大小写不导致误判。（验证：规则测试覆盖 `git status`、`git *`、反斜杠和不同大小写路径。）
- [ ] 未知工具、未知字段、非法 `action`、空或损坏的规则文本，以及 YAML 语法错误均在加载阶段给出含文件路径和规则索引的配置错误。（验证：规则加载负例测试。）
- [ ] 会话、本地、项目、用户四层规则按“会话 > 本地 > 项目 > 用户”的顺序生效；同一来源内首条匹配规则生效；更高层不命中时正确回退。（验证：规则优先级矩阵测试。）
- [ ] 缺失的用户、项目或本地规则文件按空规则集继续启动。（验证：规则加载测试使用不存在的三个路径且不抛错。）
- [ ] `strict` 未命中规则时拒绝，`default` 请求确认，`allow` 直接允许；命中的 `allow` 不受模式影响，命中的 `deny` 在任何模式下都拒绝。（验证：权限管理器模式组合测试。）
- [ ] 默认模式确认支持拒绝、本次允许、本会话允许、永久允许；空输入、EOF、中断、异常和未知选择均安全拒绝。（验证：权限管理器和终端确认测试覆盖所有输入分支。）
- [ ] 本次允许不创建规则；本会话允许在当前进程中复用、重建管理器后消失；永久允许仅写入 `.okcode/permissions.local.yaml`。（验证：检查内存规则、重建管理器、读取本地 YAML 内容。）
- [ ] 永久允许写入失败时当前调用不执行且得到可理解的拒绝结果。（验证：以失败写入替身运行确认流程，断言工具执行计数为零。）
- [ ] 每个权限拒绝都产生结构化工具失败，包含 `permission_source`、稳定拒绝类别和 `executed=false`，且不泄露项目外绝对路径或黑名单正则。（验证：断言工具结果 JSON 与终端摘要文本。）
- [ ] 默认六项工具都声明了正确的权限目标：三个文件工具为必填路径、两个搜索工具为可选路径、命令工具为命令文本。（验证：检查注册表工具定义中的权限元信息。）

## 集成

- [ ] 正式 CLI 启动时，在创建 Provider 和 App 前加载权限 YAML、创建权限管理器并注入 `ToolExecutor`。（验证：CLI 装配测试观察执行器持有权限管理器。）
- [ ] 权限 YAML 无效时 CLI 显示配置错误、返回退出码 2，且 Provider 与 App 都不创建。（验证：CLI 测试替身记录工厂调用次数。）
- [ ] `.okcode/permissions.yaml` 可被 Git 跟踪，而 `.okcode/permissions.local.yaml` 被 Git 忽略。（验证：分别运行 `git check-ignore -v`；本地规则显示忽略规则，共享规则不匹配任何忽略规则。）
- [ ] `/permissions` 只展示当前状态，不调用 Provider，也不写入对话历史。（验证：会话测试检查 Provider 请求为空、`messages` 不变并产出权限状态事件。）
- [ ] `/permissions strict`、`/permissions default`、`/permissions allow` 立即切换当前进程模式；无效参数不改变当前模式。（验证：连续会话命令测试检查事件与管理器状态。）
- [ ] 模型在同一响应中请求多个工具时，确认和预检按原始调用顺序串行完成；通过预检的只读工具仍并发运行，有副作用工具保持串行。（验证：会话调度测试检查确认顺序、工具最大并发数和调用顺序。）
- [ ] 在一个只读批次中，某个调用被拒绝不会阻止其他已允许调用执行；所有结果仍按模型请求顺序写回工具消息。（验证：混合允许/拒绝工具批次的会话测试。）
- [ ] 黑名单、沙箱、规则、严格模式和用户拒绝都不会被当作未知工具，从而不触发未知工具连续上限。（验证：拒绝后继续场景检查停止原因不为 `unknown_tool_limit`。）
- [ ] 可控 Provider 先请求被拒绝的工具、再收到结构化失败结果、随后发出安全替代调用或正式回答时，Agent Loop 正常继续并只在最终回答后提交完整历史。（验证：会话集成测试检查两次 Provider 请求和最终历史角色序列。）
- [ ] 未使用受保护工具的普通文本回复、既有工具参数失败、超时、输出截断、多工具调度、Plan Mode 和 Provider 序列化测试保持通过。（验证：运行全量测试集。）

## 终端交互

- [ ] 欢迎信息显示当前权限模式，`/permissions` 输出显示默认模式、当前模式和用户/项目/本地规则路径，且文本为简体中文。（验证：使用 `Console` 捕获可见终端文本。）
- [ ] 默认确认显示工具名和项目相对路径或完整命令，并提供拒绝、本次、本会话、永久四种选择；不显示项目外绝对路径。（验证：终端单元测试检查渲染文本。）
- [ ] 权限拒绝后的工具摘要显示“未执行”和决定来源，不打印黑名单正则、外部绝对路径或其他不必要内部细节。（验证：渲染一个权限拒绝结果，检查可见文本和敏感字段缺失。）
- [ ] 权限状态与确认输出不会破坏既有 `[思考：...]` 绿色区域、回答分隔线、`回答：` 标签和 Token/工具状态的行序。（验证：运行既有及新增终端测试，同时断言 ANSI 样式和去色后的可见文本顺序。）

## 编译与自动化测试

- [ ] 权限黑名单、规则和管理器测试通过。（验证：`uv run pytest tests/unit/test_permissions_blacklist.py tests/unit/test_permissions_rules.py tests/unit/test_permissions_manager.py -q`。）
- [ ] 工作区、执行器、会话、终端和 CLI 权限集成测试通过。（验证：`uv run pytest tests/unit/test_tools_workspace.py tests/unit/test_tools_executor.py tests/unit/test_conversation.py tests/unit/test_terminal.py tests/unit/test_cli.py -q`。）
- [ ] 全部自动化测试通过，不访问真实模型服务，也不执行真实危险命令。（验证：`uv run pytest -q`。）
- [ ] 代码格式和静态检查通过。（验证：`uv run ruff format --check .` 与 `uv run ruff check .`。）

## 端到端场景

- [ ] 场景 1：默认模式下模型请求 `run_command(git status)`，用户选择“仅本次允许”。
  验证：终端先显示确认信息；命令只执行一次；当前调用成功；再次相同调用重新进入确认；没有产生本地 YAML 规则。

- [ ] 场景 2：默认模式下模型请求 `write_file(src/new.py)`，用户选择“本会话允许”，随后模型再次请求同一路径。
  验证：首次确认后创建会话规则；第二次调用不再询问；重启 OkCode 后同一调用重新需要确认或按持久规则处理。

- [ ] 场景 3：默认模式下模型请求一个未命中规则的安全命令，用户选择“永久允许”。
  验证：`.okcode/permissions.local.yaml` 创建或追加精确 `allow` 规则；当前调用执行；重新创建权限管理器后相同调用不再询问；Git 将该文件识别为忽略文件。

- [ ] 场景 4：`allow` 模式且用户/项目规则尝试放行黑名单命令。
  验证：命令仍被拒绝，未启动子进程，工具结果来源为 `blacklist`，Agent Loop 收到失败结果后继续请求模型。

- [ ] 场景 5：模型请求读取或写入经符号链接指向项目外的路径。
  验证：路径在解析后被拒绝，项目外文件未读写，工具结果不泄露项目外绝对路径，模型可继续选择项目内替代路径。

- [ ] 场景 6：同一响应包含两个只读工具调用，其中一个项目规则明确 `deny`，另一个被 `allow` 规则放行。
  验证：确认按调用顺序完成；被拒绝调用不执行；被允许调用仍执行；回灌给模型的两个结果保持原调用顺序。
